Kaeso has the providers below built in, listed by name. [Providers](providers.md) explains how to use one and what differs between them, and [APIs by provider](provider-apis.md) shows which APIs each one serves. An organization can also add a server of its own that speaks one of these formats ([custom providers](../console/custom-providers.md)).

## Columns

- **Provider.** The name the console shows, then the id. The id names the provider in model names, such as `groq/llama-3.3-70b-versatile`, and in [settings](../self-hosting/configuration.md#provider-settings).
- **Formats.** The API formats Kaeso calls the provider with. A model uses the first one unless its **Sends as** value names another ([a model's values](../console/models-and-aliases.md#change-a-models-values)). **Embeddings** and **Gemini Embeddings** mean the provider has embeddings models, which serve `/v1/embeddings`. **Token counts** means it counts tokens for `/v1/messages/count_tokens` and `/v1/responses/input_tokens`. Decisions go through each provider's own decisions API, which [APIs by provider](provider-apis.md) lists.
- **Host.** The host of the provider's default base URL, which the install must reach. A [base URL you set](../self-hosting/configuration.md#provider-settings) replaces it.
- **Key.** Where you create a key, and how the key starts ([provider keys](../console/provider-keys.md)).

## Notes

What else to know about some providers. [Provider profiles](../development/kpp/openai-chat-providers.md#provider-profiles) lists every Chat Completions field a provider renames or refuses:

- **Baseten.** Baseten Model APIs, the shared endpoint of models Baseten hosts, such as `zai-org/GLM-5.3`, `moonshotai/Kimi-K3` and `deepseek-ai/DeepSeek-V4.1-Flash-1017`; a dedicated deployment has its own address and is a [custom provider](../console/custom-providers.md). Model ids name the model's maker, and some start with another provider's id, such as `openai/gpt-oss-120b`, so call them as `baseten/openai/gpt-oss-120b` ([how a request names a model](../console/models-and-aliases.md#how-a-request-names-a-model)). Gets every app's output limit as `max_tokens`, `developer` messages as `system` messages and the end user's id as `user`. A model's thinking reaches apps in every format, from `reasoning_content`, and goes back to Baseten there on later turns, as Beam requires; GLM 5.2 and Nemotron 3 Ultra think only with `chat_template_args`, which only a Chat app can send. Kaeso calls Chat Completions only: Baseten's Messages endpoint takes no thinking or images, and Model APIs serve no embeddings, images or audio. Kaeso refuses token counts, which Baseten doesn't serve.
- **Cerebras.** Cerebras Inference, with models such as `gpt-oss-120b` and `qwen-3.8-27b`. Gets `developer` messages as `system` messages, the end user's id as `user`, the text of a system message that Claude Code or Codex sends after the first turn in the next user turn, and a function without parameters with an empty parameter schema. Grok CLI's replayed `reasoning_content` reaches it as `reasoning`. It refuses a conversation that ends with an assistant message, because Cerebras answers it anew, and a `refusal` on an assistant message. Cerebras answers any field it doesn't know, such as `store`, with 400, and takes images only as data URIs. A model's thinking reaches apps in every format; `gpt-oss-120b` thinks at `reasoning_effort` `low`, `medium` or `high`, `qwen-3.8-27b` also at `none`, and Kaeso refuses other levels.
- **Cloudflare AI Gateway.** Cloudflare's REST API, which serves third-party models such as `anthropic/claude-sonnet-5.5` and `openai/gpt-6-luna`, paid with Cloudflare's Unified Billing credits or the provider keys stored on the gateway, and Workers AI models such as `@cf/zai-org/glm-4.7-flash`, billed through Workers AI. A key is a Cloudflare API token with **Workers AI Read**, and names the account it calls and, optionally, the gateway its requests go through; without a gateway, third-party models go through the account's `default` gateway, which Cloudflare creates on the first such request, and Workers AI models are called directly ([provider keys](../console/provider-keys.md#cloudflare-ai-gateway-keys)). So a key without a gateway is how you call Workers AI alone. Kaeso sends each model in the format Cloudflare lists for it: Claude models as Messages, the models Cloudflare serves only through Responses as Responses, and every other model as Chat Completions. A gateway's aliases (`custom/…`) and dynamic routes (`dynamic/…`) are added as custom models; a dynamic route takes Chat Completions only. Workers AI's embeddings models, such as `@cf/baai/bge-m3` and `@cf/qwen/qwen3-embedding-0.6b`, serve `/v1/embeddings`; Kaeso refuses `dimensions`, which they ignore, and estimates their usage, which Cloudflare doesn't report. Kaeso refuses token counts, which Cloudflare doesn't serve. **Check availability** finds Workers AI models in Cloudflare's model search; whether Cloudflare serves another model takes a request it bills, so the check confirms the key and its account and calls the model inconclusive. Workers AI models take images as base64 data, not as links, and some accept only some reasoning efforts, which the catalogue lists. Each request's log names Cloudflare's log entry as its upstream request. Cloudflare's Clef models answer [decisions](../api/decisions.md) in any decision format; Kaeso sends them as System One to Workers AI's `/ai/run/@cf/cloudflare/{model}`.
- **Cohere.** Cohere's [Compatibility API](https://docs.cohere.com/docs/compatibility-api), which covers part of Cohere's own API: documents, citations and rerank aren't reachable through it. Cohere refuses some fields, such as `logit_bias` and `parallel_tool_calls: false`, and gets a single `stop` string as a list. Its reasoning models think at `reasoning_effort` `none` or `high` only. Its Embed models, such as `embed-v4.0`, aren't in KPMR: add them as custom models that send as Embeddings, with their price.
- **DeepInfra.** DeepInfra's serverless open models, such as `deepseek-ai/DeepSeek-V4-Flash-0731`, `openai/gpt-oss-120b` and `Qwen/Qwen3.8-27B`, and its embeddings models, such as `BAAI/bge-m3` and `Qwen/Qwen3-Embedding-8B`, which serve `/v1/embeddings`. A provider key needs the `inference` scope, which every new key has. Model ids name the model's maker, and some start with another provider's id, such as `openai/gpt-oss-120b`, so call them as `deepinfra/openai/gpt-oss-120b` ([how a request names a model](../console/models-and-aliases.md#how-a-request-names-a-model)). Gets every app's output limit as `max_tokens`, `developer` messages as `system` messages, the end user's id as `user`, and video as `video_url` parts for the models that take video. A model's thinking reaches apps in every format, from `reasoning_content`. Kaeso refuses the fields DeepInfra's API leaves out and would drop without a word, such as `logit_bias`, `top_logprobs` and `store`, and token counts, which DeepInfra serves only beside its Anthropic-compatible endpoint. DeepInfra lists its models without checking the key, so **Check availability** can't spot a wrong key; the first request with it reports the refused key. Its images, speech, transcriptions and videos aren't in KPMR yet.
- **DeepSeek.** Gets `developer` messages as `system` messages.
- **Fireworks AI.** Fireworks AI's serverless open models, such as `accounts/fireworks/models/glm-5p3-flash` and `accounts/fireworks/models/kimi-k3`, called by their full resource names (`fireworks-ai/accounts/fireworks/models/kimi-k3`) at `https://api.fireworks.ai/inference`. Kaeso calls Chat Completions by default; a model's **Sends as** value can choose Messages, Fireworks' Anthropic-compatible endpoint. Gets the end user's id as `user`, and video as `video_url` parts for the models that take video. A model's thinking reaches apps in every format, from `reasoning_content`, and goes back to Fireworks there. Fireworks lowers a `max_tokens` that doesn't fit the context window instead of refusing it, unless a Chat app sends `context_length_exceeded_behavior: "error"`. Its embeddings models, `qwen3-embedding-8b` and older ones under their Hugging Face ids such as `nomic-ai/nomic-embed-text-v1.5`, serve `/v1/embeddings`. Kaeso refuses token counts, which Fireworks doesn't serve. For US-only processing, set Fireworks' [base URL](../self-hosting/configuration.md#provider-settings) to `https://us.api.fireworks.ai/inference`.
- **Gemini Enterprise Agent Platform.** Google Cloud's platform for Gemini models, such as `gemini-3.5-flash` and `gemini-3.1-pro-preview`. Kaeso calls it in Gemini's own format, as it calls Google AI Studio, and writes `role` on every content, as the platform's token counting reference asks. A provider key is either an express mode API key, sent as `x-goog-api-key` to `aiplatform.googleapis.com`, which reaches only the Gemini models that express mode lists, or a service account's JSON key, with which Kaeso gets access tokens from Google by itself and calls the key's project in the location you choose ([add a Google Cloud service account key](../console/provider-keys.md#add-a-google-cloud-service-account-key)). Each location has its own host: `aiplatform.googleapis.com` for `global`, `aiplatform.us.rep.googleapis.com` and `aiplatform.eu.rep.googleapis.com` for the multi-regions `us` and `eu`, and `<location>-aiplatform.googleapis.com` for a region such as `us-east5`. A [base URL you set](../self-hosting/configuration.md#provider-settings), such as a Private Service Connect endpoint, replaces every location's host. Kaeso sends each model in the format its family uses: Gemini models in Gemini's format, Claude models (`claude-*`, such as `claude-opus-5-5@default`) in the Messages format through the platform's `rawPredict`, and partner and open models, whose ids name their publisher (`meta/llama-4-maverick-17b-128e-instruct-maas`), as Chat Completions through the platform's OpenAI-compatible endpoint. A custom model follows the same rule, and its **Sends as** value chooses another format. Claude and partner models need a service account key; Kaeso refuses them for an express mode key before sending. Mistral models, which the platform serves only in Mistral's own format, are refused, as are the platform's embeddings models. The OpenAI-compatible endpoint takes some fields without acting on them, such as `logit_bias`, `logprobs` and `store`, which Kaeso refuses. Token counts work for Gemini and Claude models. **Check availability** counts the tokens of a one-word prompt, which Google doesn't charge for, so it spots a wrong key and a Gemini or Claude model the key's project or location doesn't serve; for partner models it can't tell. Service account keys also need `oauth2.googleapis.com`.
- **Google AI Studio.** The Gemini API of Google AI Studio, with Gemini models such as `gemini-3.5-flash` and `gemini-3.1-pro-preview`, the Gemma models and the embeddings models `gemini-embedding-2` and `gemini-embedding-001`. Kaeso calls it in Gemini's own format with the key in `x-goog-api-key`, so apps in every format reach it and Gemini's thought signatures survive tool calls. Gemini 3 models think at the effort levels KPMR lists for them, sent as `thinkingLevel`. Gemini 2.5 models list none: an Anthropic app's `budget_tokens` goes as `thinkingBudget`, and another app's effort is left out and named in `kaeso-left-out`. Hosted web search is left out, because Gemini's `googleSearch` takes none of its settings. AI Studio keys start with `AIza` or `AQ.`. A key on the free tier has a small daily quota per model; past it, Google answers 429, which apps get as a rate limit. **Check availability** spots a wrong key. Gemini Enterprise Agent Platform, Google Cloud's platform for Gemini models, is a provider of its own.
- **Groq.** Gets `developer` messages as `system` messages, and refuses some fields, such as `logit_bias`.
- **Hugging Face.** Hugging Face Inference Providers, a router that passes each request on to one of the providers that serve the model, such as Groq, Cerebras or Novita, with open models such as `openai/gpt-oss-120b`, `deepseek-ai/DeepSeek-V4.1-Flash-1017` and `Qwen/Qwen3.8-27B`. A provider key is a fine-grained Hugging Face access token with the **Make calls to Inference Providers** permission, and usage is billed to the token's owner. Model ids name the model's maker, so call them as `huggingface/openai/gpt-oss-120b` to keep them from reaching the maker's own provider ([how a request names a model](../console/models-and-aliases.md#how-a-request-names-a-model)). The router picks the fastest provider; a suffix on the model id picks one, such as `openai/gpt-oss-120b:groq`, or a policy, `:cheapest` or `:preferred`, so add the model with its suffix to use it. Gets every app's output limit as `max_tokens` and `developer` messages as `system` messages, and leaves out the end user's id, which the router doesn't take. A model's thinking reaches apps in every format, from `reasoning_content` or `reasoning`, whichever the provider behind the router sends. The router lists its models without checking the key, so **Check availability** can't spot a wrong key; the first request with it reports the refused key. Kaeso calls only Chat Completions: the router serves embeddings, images and audio only through Hugging Face's own task API, and Kaeso refuses token counts, which Hugging Face doesn't document.
- **ElevenLabs.** ElevenLabs' speech, dialogue, sound effects, music, voice changer and speech to text, called in ElevenLabs' own format with the key in `xi-api-key`. ElevenLabs writes no text, so it serves the [Audio API](../api/audio.md), the [ElevenLabs API](../api/elevenlabs.md) and, with its Veo and Seedance models, the [Videos API](../api/videos.md), not chat. Voices go by their ElevenLabs id. Kaeso reads the characters ElevenLabs bills from its `character-cost` header. For EU or US data residency, set ElevenLabs' [base URL](../self-hosting/configuration.md#provider-settings) to `https://api.eu.residency.elevenlabs.io` or `https://api.us.elevenlabs.io`.
- **MiniMax.** MiniMax's Anthropic-compatible API, with `MiniMax-M3` and `MiniMax-M3.1-Flash`, the only models MiniMax serves on it; its M2 models are retired. Kaeso calls it in the Messages format with the key in `x-api-key`, so apps in every format reach it. Kaeso refuses what MiniMax accepts without acting on it: `top_k`, `stop_sequences` (a Chat app's `stop`), `mcp_servers`, `container`, a `temperature` other than 1, a `top_p` other than 0.95 and a `tool_choice` other than `auto`. Claude Code's `context_management` that only clears thinking is left out and named in `kaeso-left-out`. Images go by URL or as base64, and MiniMax refuses documents itself. `MiniMax-M3.1-Flash` always thinks and refuses thinking turned off. MiniMax signs its thinking blocks itself, so an Anthropic app should send a conversation with them only to MiniMax models; Anthropic refuses their signatures. Kaeso refuses token counts, because MiniMax answers them in another shape than Anthropic's. For mainland China, set MiniMax's [base URL](../self-hosting/configuration.md#provider-settings) to `https://api.minimax.cn/anthropic` and use a key from platform.minimax.cn.
- **Mistral.** Gets `developer` messages as `system` messages, and some fields under its own names, such as `seed` as `random_seed`. It refuses others, such as `logit_bias`, and a conversation that ends with an assistant message.
- **Moonshot.** The Kimi API, with Moonshot's Kimi models, such as `kimi-k3` and `kimi-k2.6`. Gets `developer` messages as `system` messages, and an app's prefilled assistant message with Moonshot's `partial: true`, so the reply continues it. It refuses some fields, such as `parallel_tool_calls: false` and `store`, which Moonshot accepts without acting on them. Kimi models fix their sampling: Kaeso refuses a `temperature` other than 1 before sending, and Moonshot refuses other values of `top_p`, `n` and the penalties. A model's thinking reaches apps in every format. The K3 models think at `reasoning_effort` `low`, `high` or `max`, and Kaeso refuses other levels; `kimi-k2.6` stops thinking at `none`, and `kimi-k2.7-code` always thinks. Kimi models refuse `tool_choice: "required"` while they think.
- **Nebius Token Factory.** Nebius' serverless open models, such as `zai-org/GLM-5.3`, `moonshotai/Kimi-K3` and `deepseek-ai/DeepSeek-V4.1-Flash-1017`; a `-fast` suffix on a model id chooses its faster flavor, which you add as a custom model with its price. Gets `developer` messages as `system` messages, the end user's id as `user`, and video as `video_url` parts for the models that take video. A model's thinking reaches apps in every format, from `reasoning_content` or `reasoning`. Its embeddings models, such as `Qwen/Qwen3-Embedding-8B`, serve `/v1/embeddings`. Nebius serves no Messages, images, audio or token counts. Public endpoints run in a region Nebius chooses; a dedicated endpoint in a region of your choice has its own host, such as `https://api.tokenfactory.eu-north1.nebius.com`, which you set as Nebius' [base URL](../self-hosting/configuration.md#provider-settings).
- **NVIDIA.** NVIDIA's hosted NIM API, the models of build.nvidia.com, such as `nvidia/nemotron-3-super-120b-a12b`, `moonshotai/kimi-k2.6` and `z-ai/glm-5.3-flash`, and its embeddings models, such as `nvidia/nemotron-3.5-embed-1b`. A NIM container you run yourself is a [custom provider](../console/custom-providers.md#server-software) of the **NVIDIA NIM** kind instead. Model ids name the model's publisher, so call one as `nvidia/moonshotai/kimi-k2.6` to keep it from reaching the publisher's own provider ([how a request names a model](../console/models-and-aliases.md#how-a-request-names-a-model)). Gets every app's output limit as `max_tokens` and `developer` messages as `system` messages, and leaves out the end user's id, which NVIDIA's API doesn't take. A model's thinking reaches apps in every format, from `reasoning_content`; models such as Nemotron turn it on with `chat_template_kwargs` or `reasoning_effort`, which a Chat app sends as written. Retrieval embeddings models such as `nvidia/nv-embedqa-e5-v5` need `input_type`, `query` or `passage`, which only an Embeddings app can send. NVIDIA answers a key it doesn't know with 403, so apps get it as a key that isn't allowed the request, and a retired model with 410 before it checks the key. NVIDIA lists its models without checking the key, so **Check availability** can't spot a wrong key; the first request with it reports it. Kaeso refuses token counts, which NVIDIA doesn't serve.
- **Ollama Cloud.** Models that Ollama runs on its own servers, such as `gpt-oss:120b`. Model ids keep Ollama's tag after a colon. Gets every app's output limit as `max_tokens`, because Ollama ignores `max_completion_tokens`, and refuses `logprobs`, `top_logprobs` and `logit_bias`, which Ollama accepts without acting on them. A model's thinking reaches apps in every format. Ollama's free plan includes only some models: for the others Ollama answers 402, which apps get as a refused provider key. Ollama lists its models without checking the key, so **Check availability** can't spot a wrong key; the first request with it reports the refused key. A local Ollama server needs no key; add it as a [custom provider](../console/custom-providers.md#server-software) whose server is Ollama.
- **OpenAI.** A provider key can also be a ChatGPT account, whose requests use its ChatGPT plan under OpenAI's rules for it ([sign in with a ChatGPT account](../console/provider-keys.md#sign-in-with-a-chatgpt-account)).
- **OpenRouter.** Model ids name the model's maker, such as `anthropic/claude-sonnet-4.5`. Call them as `openrouter/anthropic/claude-sonnet-4.5`, so they never reach the maker's own provider ([how a request names a model](../console/models-and-aliases.md#how-a-request-names-a-model)). Kaeso records costs at the catalogue's prices, not at the `usage.cost` OpenRouter reports. OpenRouter lists its models without checking the key, so **Check availability** can't spot a wrong key; the first request with it reports the refused key.
- **Perplexity.** Perplexity's Sonar models, `sonar`, `sonar-pro`, `sonar-reasoning-pro` and `sonar-deep-research`, which search the web and answer with citations, through Sonar chat completions at `/v1/sonar`. Perplexity ended support for Sonar chat completions on 2026-09-27 and answers them with its Agent API behind the same endpoint, so KPMR lists the Sonar models as deprecated; Kaeso doesn't call the Agent API. A Chat app's search fields, such as `search_mode`, `search_domain_filter` and `web_search_options`, reach Perplexity as written, and its replies keep `citations`, `search_results` and `related_questions`. Apps in other formats can't send search fields, and get the answer with its `[1]` markers but without the sources. Gets every app's output limit as `max_tokens` and `developer` messages as `system` messages, and leaves out the end user's id, which Perplexity takes only in a header. Kaeso refuses tools, log probabilities, penalties, `seed` and `stream_mode`, which Perplexity's API reference doesn't list, and token counts, which it doesn't serve. Perplexity's replies report a `usage.cost` that includes a fee for the searches; Kaeso records costs at the catalogue's token prices, which leave that fee out. Perplexity's model listing names the Agent API's models, not the Sonar ids, so **Check availability** calls a Sonar model inconclusive, not unavailable.
- **QwenCloud.** Alibaba's model platform outside mainland China, formerly Alibaba Cloud Model Studio, in its Singapore region, with Qwen models such as `qwen3.7-flash` and other makers' models such as `kimi-k3`. A key works only in the region it was created in. For the China (Beijing) region, which KPMR lists as `alibaba-cn`, set QwenCloud's [base URL](../self-hosting/configuration.md#provider-settings) to `https://dashscope.aliyuncs.com/compatible-mode` and use a key from there; an install reaches one region. Gets `developer` messages as `system` messages, and refuses fields QwenCloud accepts without acting on them, such as `logit_bias` and `web_search_options`. An app's thinking reaches the model as `enable_thinking`, an Anthropic app's `budget_tokens` as `thinking_budget`, and a reasoning effort only goes to models that list effort levels, such as `qwen3.8-max`. A Chat app's `max_tokens` limits only the answer, not the thinking; `max_completion_tokens` limits both. Some models only think and refuse thinking turned off, and `qwq-plus` answers only streamed requests: the app gets QwenCloud's 400. Its embeddings models, such as `text-embedding-v4`, aren't in KPMR: add them as custom models that send as Embeddings, with their price. Its Wan video models serve the [Videos API](../api/videos.md) through DashScope's own task API at the root of the same host, and the image, speech and transcription models its OpenAI-compatible mode doesn't serve go to DashScope's own API there too ([Images API](../api/images.md), [audio](../api/audio.md)).
- **SambaNova.** SambaCloud, SambaNova's hosted models, such as `gpt-oss-120b`, `GLM-5.3` and `gemma-4-31B-it`. Kaeso calls Chat Completions by default; a model's **Sends as** value can choose Messages, SambaNova's Anthropic-compatible endpoint. A model's thinking reaches apps in every format, from `reasoning`; DeepSeek-V3.2 and Gemma 4 think only when a Chat app sends `chat_template_kwargs: {"enable_thinking": true}`. Kaeso refuses `frequency_penalty` and `presence_penalty`, which SambaNova accepts without acting on them, and leaves out the end user's id and a Responses app's cache key, which SambaNova's API doesn't take. Token counts work for every SambaNova model: Kaeso counts them at SambaNova's Messages token count. SambaCloud serves no embeddings and no Whisper; both are SambaStack features. SambaNova lists its models without checking the key, so **Check availability** can't spot a wrong key; the first request with it reports the refused key. For a SambaStack install, set SambaNova's [base URL](../self-hosting/configuration.md#provider-settings) to its address.
- **Scaleway.** Scaleway Generative APIs, serverless models hosted in Paris, such as `gpt-oss-120b`, `qwen3.5-397b-a17b` and `mistral-small-3.2-24b-instruct-2506`; Scaleway keeps them in Europe. A provider key is an IAM API key's secret key with a Generative APIs permission set. It reaches the key's default Project; for another Project, set Scaleway's [base URL](../self-hosting/configuration.md#provider-settings) to `https://api.scaleway.ai/<project-id>`. Gets `developer` messages as `system` messages and leaves out the end user's id, which Scaleway's API doesn't take. A model's thinking reaches apps in every format, from `reasoning_content` in replies and `reasoning` in streams. Its embeddings models, such as `bge-multilingual-gemma2`, serve `/v1/embeddings`, and `whisper-large-v3` serves transcriptions in the `json` form only, billed by the minute of audio. Scaleway answers a key it doesn't know with 403, as it answers a key without a Generative APIs permission, so apps get it as a key that isn't allowed the request. Kaeso refuses token counts, which Scaleway doesn't serve.
- **SiliconFlow.** SiliconFlow's international API, with open models such as `deepseek-ai/DeepSeek-V4-Flash`, `Qwen/Qwen3.5-397B-A17B` and `zai-org/GLM-5.3`, its embeddings models, such as `Qwen/Qwen3-Embedding-8B`, CosyVoice speech and SenseVoice transcriptions. For the China endpoint, which KPMR lists as `siliconflow-cn`, set SiliconFlow's [base URL](../self-hosting/configuration.md#provider-settings) to `https://api.siliconflow.cn` and use a key from there; an install reaches one of them. Model ids name the model's maker, and some start with another provider's id, such as `openai/gpt-oss-120b`, so call them as `siliconflow/openai/gpt-oss-120b` ([how a request names a model](../console/models-and-aliases.md#how-a-request-names-a-model)). Gets every app's output limit as `max_tokens`, which limits only the answer, `developer` messages as `system` messages, and leaves out the end user's id, which SiliconFlow's API doesn't take. An app's thinking reaches the model as `enable_thinking` and an Anthropic app's `budget_tokens` as `thinking_budget`; a model's thinking reaches apps in every format, from `reasoning_content`. Speech takes voices named after their model, such as `FunAudioLLM/CosyVoice2-0.5B:alex`, and transcriptions take only the file and the model. Kaeso refuses images and videos, which SiliconFlow serves in a form of its own, and token counts, which it doesn't serve.
- **SpaceX.** xAI's API, with models such as Grok. A provider key can also be a Grok account whose plan includes API access, as an experimental option ([sign in with a Grok account](../console/provider-keys.md#sign-in-with-a-grok-account)).
- **Standard Compute.** Monthly plans with a compute budget for frontier and open models. Its router `standardcompute`, **Smart routing**, picks a model for each request from the models enabled on Standard Compute's dashboard, and comes first when you add Standard Compute's models. Its replies name the model `StandardCompute`; only Standard Compute's request logs show which model answered. An exact id, such as `anthropic/claude-sonnet-5.5`, pins one model, and the `:eu` and `:us` variants, such as `openai/gpt-5.6-luna:eu`, run only on provider endpoints in Europe or the United States. Standard Compute bills a plan, not tokens, so its models have no prices: a request's cost shows as **Unknown**, and a spend budget refuses the models unless an admin sets their prices by hand ([features a spend budget can't price](../console/limits-and-budgets.md#features-a-spend-budget-cant-price)). A used-up monthly budget reaches apps as a provider key refused for billing reasons, and Standard Compute's rate limit as a rate limit with its `retry-after`. A model's thinking reaches apps in every format, from `reasoning`. Kaeso calls Chat Completions only: Standard Compute's Messages endpoint ignores thinking, and it serves no embeddings, images or audio. Kaeso refuses token counts, which Standard Compute only estimates from a request's size, and video, which its models' providers don't take as links. Standard Compute lists its models without checking the key, so **Check availability** can't spot a wrong key, and calls a model the key's list leaves out inconclusive, not unavailable. For the EU or US endpoint, set Standard Compute's [base URL](../self-hosting/configuration.md#provider-settings) to `https://eu.stdcmpt.com` or `https://us.stdcmpt.com`.
- **TypeSafe.** TypeSafe's System One models, Jev 1.14 (`jev-1.14.0`) and Jev 1.13 (`jev-1.13.0`), with the aliases `jev-latest` and `jev-preview`. They answer decision questions and write no text, so they serve the [Decisions API](../api/decisions.md) in every decision format, not chat. Kaeso sends each request to TypeSafe's `/v1/systemone`, with images as `assets` and an app's uploaded images as parts again. A request with an image or a box question gets `TypeSafe-Danger-Zone-Images: true`. Kaeso also sends `TypeSafe-Danger-Zone-Long-Context: true` when it estimates the state and every question above 64k tokens, or the state and any one question above 32k. It counts 4 bytes of text a token and leaves images out, and `kaeso-adapted` names the header as `long_context`. Long context costs the same, but TypeSafe refuses a longer request without it. Box questions need Jev 1.14, and output tokens are free. A key TypeSafe doesn't know (401) and a request without a key (403) reach apps as a refused provider key. **Check availability** reads TypeSafe's model listing, which names models and aliases in a shape of its own; a model it leaves out is inconclusive, not unavailable.
- **Upstage.** Upstage's Solar models, `solar-pro4` and `solar-mini4`, aliases of dated snapshots such as `solar-pro4-260806`, which replies name, and its embeddings models `solar-embedding-2-query` and `solar-embedding-2-passage`, which serve `/v1/embeddings`: embed questions with the `-query` model and the documents they search with the `-passage` one; their vectors have 1,024 dimensions, so Kaeso refuses `dimensions`. Gets every app's output limit as `max_tokens` and `developer` messages as `system` messages, and leaves out the end user's id, which Upstage's API doesn't take. Solar models think only when an app asks: a reasoning effort from `low` to `max` turns thinking on, and it reaches apps in every format, from `reasoning`. Kaeso refuses the fields Upstage's API reference doesn't list, such as `stop` (an Anthropic app's `stop_sequences`), `seed` and `logit_bias`, and token counts, which Upstage leaves to its published tokenizer. Upstage's model listing needs a valid key and isn't documented, so **Check availability** calls a model it leaves out inconclusive, not unavailable. For the Korea region, in closed beta, set Upstage's [base URL](../self-hosting/configuration.md#provider-settings) to `https://kr.api.upstage.ai`; it serves `solar-mini4` only.
- **Vercel.** Vercel AI Gateway, another gateway whose own routing and fallbacks run behind Kaeso. Model ids name the model's maker, such as `openai/gpt-5-nano`. Call them as `vercel/openai/gpt-5-nano`, so they never reach the maker's own provider ([how a request names a model](../console/models-and-aliases.md#how-a-request-names-a-model)). A model's **Sends as** value can choose Responses or Messages, which Vercel serves too; on Messages, Vercel passes Anthropic's `cache_control` on to Claude models. Kaeso records costs at the catalogue's prices, not at the `usage.cost` Vercel reports, which leaves out Vercel's own surcharges. Vercel counts tokens exactly only for Claude models and estimates the rest, so Kaeso refuses token counts for every Vercel model. Vercel answers for a model without checking the key, so **Check availability** can't spot a wrong key; the first request with it reports the refused key. A Vercel account on the free tier can't call paid models such as Claude: Vercel answers 403, which apps get as a refused provider key, and the request log keeps Vercel's reason.
- **Z.ai.** Z.ai's Anthropic-compatible API, with GLM models such as `glm-5.3` and `glm-4.6`. Kaeso calls it in the Messages format with the key in `x-api-key`, so apps in every format reach it, and an Anthropic app's request goes as the app wrote it. Z.ai documents no list of the Anthropic fields it takes, so Kaeso sends them all and leaves any refusal to Z.ai; Z.ai caches repeated prompts on its own. Z.ai sends its own error codes: an empty balance (`1113`) reaches apps as a refused provider key instead of a rate limit, an overloaded service (`1305`) as overloaded, and a prompt that is too long (`1261`) as one, so Claude Code compacts the conversation. Kaeso refuses token counts, which Z.ai doesn't document. **Check availability** spots a wrong key; Z.ai documents no model listing, so whether it spots a model Z.ai doesn't serve is untested. Z.ai bills each call by the key's type and allows GLM Coding Plan keys only in the coding tools it names, so use a Standard API key. For mainland China, set Z.ai's [base URL](../self-hosting/configuration.md#provider-settings) to `https://open.bigmodel.cn/api/anthropic` and use a key from bigmodel.cn.
