Kaeso has the providers below built in, listed by name. [Providers](providers.md) explains how to use one and what differs between them, and [APIs by provider](provider-apis.md) shows which APIs each one serves. An organization can also add a server of its own that speaks one of these formats ([custom providers](../console/custom-providers.md)).

## Columns

- **Provider.** The name the console shows, then the id. The id names the provider in model names, such as `groq/llama-3.3-70b-versatile`, and in [settings](../self-hosting/configuration.md#provider-settings).
- **Formats.** The API formats Kaeso calls the provider with. For a provider without token counts among them, Kaeso estimates the count, apart from audio and video ([what differs between providers](providers.md#what-differs-between-providers)). A model uses the first one unless its **Sends as** value names another ([a model's values](../console/models-and-aliases.md#change-a-models-values)). Without one, an Anthropic app's request goes as it came, untranslated, to the Messages API of DeepSeek, Moonshot (K3 models), QwenCloud (Qwen models), Baidu Qianfan, DeepInfra, OpenRouter, Hugging Face, Ollama Cloud, Tencent TokenHub, Fireworks AI, SambaNova and Vercel ([native Messages APIs](../development/kpp/anthropic-messages-providers.md#native-messages-apis)). **Embeddings** and **Gemini Embeddings** mean the provider has embeddings models, which serve `/v1/embeddings`. **Cohere Rerank**, **Jina Rerank** and **Voyage Rerank** mean it has rerank models, which serve `/v1/rerank`. **Token counts** means it counts tokens for `/v1/messages/count_tokens` and `/v1/responses/input_tokens`. Decisions go through each provider's own decisions API, which [APIs by provider](provider-apis.md) lists.
- **Host.** The host of the provider's default base URL, which the install must reach. A [base URL you set](../self-hosting/configuration.md#provider-settings) replaces it.
- **Key.** Where you create a key, and how the key starts ([provider keys](../console/provider-keys.md)).

## Notes

What else to know about some providers. A provider pointed at another region with its base URL keeps the models and prices of its default region ([provider settings](../self-hosting/configuration.md#provider-settings)). [Provider profiles](../development/kpp/openai-chat-providers.md#provider-profiles) lists every Chat Completions field a provider renames or refuses:

- **Amazon Bedrock.** The models of your own AWS account, such as `us.anthropic.claude-sonnet-5`, `deepseek.v3.2` and `global.openai.gpt-6-sol`. A provider key is a Bedrock API key, an AWS access key, or, where the operator allows it, the gateway's own AWS identity ([Amazon Bedrock keys](../console/provider-keys.md#amazon-bedrock-keys)): a long-term Bedrock API key starts `ABSK`; a short-term one starts `bedrock-api-key-`, lasts at most 12 hours and works only in the region that made it. Kaeso signs requests with AWS credentials using Signature Version 4, in the key's region also behind a base URL of your own. Each key calls the region you choose for it, at that region's runtime endpoint `bedrock-runtime.<region>.amazonaws.com`; a [base URL you set](../self-hosting/configuration.md#provider-settings), such as a VPC endpoint, replaces every region's host. Kaeso sends each model in the format AWS's [API compatibility](https://docs.aws.amazon.com/bedrock/latest/userguide/models-api-compatibility.html) table lists for it, which the catalogue names: Claude models as Messages, at `/anthropic/v1/messages` with a Bedrock API key as `x-api-key`, the others as Chat Completions, at `/openai/v1/chat/completions`, and the chat models that answer neither, such as Amazon Nova, Meta Llama, Writer Palmyra and Claude Sonnet 4.6 and older, through Bedrock's own Converse API, at `/model/{modelId}/converse` ([Amazon Bedrock Converse](../development/kpp/bedrock-converse.md)). Inference profile ids, such as `us.…`, `eu.…` and `global.…`, are called as written; which ones a key can call depends on its region. The foundation model ids of closed-weight GPT models are refused before sending, since bedrock-runtime takes them only by an inference profile id. Kaeso estimates token counts, which bedrock-runtime counts only in its own format, and refuses `mcp_servers` and `container`, which Claude on Bedrock doesn't take. bedrock-runtime lists no models, so **Check availability** calls every model inconclusive; the first request reports a refused key.
- **AssemblyAI.** AssemblyAI's Sync API, `universal-3-6-pro`, called in AssemblyAI's own format: one upload per transcript, answered in the same request. It serves the [Audio API](../api/audio.md)'s transcriptions only, not speech. The Sync API takes audio of up to 20 minutes and 256 MB and answers within 30 seconds, otherwise with a timeout error. It detects no language and steers toward 32 (send `language` for one of them, or leave it out), labels no speakers, so `diarized_json` is refused, and times words only, from which Kaeso writes `verbose_json`, `srt` and `vtt`. For the EU, set AssemblyAI's [base URL](../self-hosting/configuration.md#provider-settings) to `https://sync.eu.assemblyai.com`, with the same keys. **Check availability** can't check an AssemblyAI key, since the Sync API has no request that does without transcribing; the first transcription shows whether it works ([AssemblyAI](../development/kpp/assemblyai.md)).
- **Azure.** Azure OpenAI and Microsoft Foundry: the models an Azure resource deploys, such as `gpt-5`, `gpt-5-mini` and DeepSeek, Grok, Llama and Mistral models, and embeddings models such as `text-embedding-3-small`, through Azure's OpenAI v1 API at `{endpoint}/openai/v1`. A key is a resource's KEY 1 or KEY 2 and names the resource's endpoint, such as `https://example.openai.azure.com`, which the resource's **Keys and Endpoint** page shows beside the key ([provider keys](../console/provider-keys.md#azure-keys)); Kaeso sends the key as `api-key`. A key may instead be a Microsoft Entra ID service principal, for resources whose key access is off: Kaeso exchanges its client secret for access tokens and sends them as a bearer. A request names a deployment, not a model: when a deployment's name isn't the model's id, set the model's **Provider model ID** to the deployment's name ([change a model's values](../console/models-and-aliases.md#change-a-models-values)). Kaeso calls Chat Completions; a model's **Sends as** value can choose Responses for deployments that take it. Chat apps get Azure's content filter results as Azure sends them; a prompt the filter blocks reaches every app as a content filter error, and a reply it stops ends with `content_filter`. Azure lists the models a resource may deploy, not its deployments, so **Check availability** confirms the key and its endpoint and calls each model inconclusive. KPMR's prices are Azure's Global Standard prices; Data Zone and Regional deployments cost more, about 10% and 21% more in Azure's price list, so set those models' prices in their values. Claude deployments, which answer only Anthropic's Messages API under `/anthropic`, and images, speech and transcriptions, which the v1 API serves only in preview, aren't reachable yet.
- **Baidu Qianfan.** Baidu AI Cloud's model platform in mainland China (百度千帆), with Baidu's ERNIE models, such as `ernie-5.1` and `ernie-5.5-flash-preview`, other makers' models, such as `deepseek-v4-pro`, `glm-5.3` and `qwen3.5-397b-a17b`, and the embeddings models `embedding-v1`, `tao-8k`, `bge-large-*` and `qwen3-embedding-*`, which serve `/v1/embeddings` at their fixed size, so Kaeso refuses `dimensions`. Qianfan's API sits at `/v2`, so the base URL `https://qianfan.baidubce.com/v2` ends there and Kaeso leaves `/v1` out of its paths. The catalogue lists the China service's models, with its CNY prices in USD; for the international service, which has its own accounts, model ids and prices, set Qianfan's [base URL](../self-hosting/configuration.md#provider-settings) to `https://api.baiduqianfan.ai/v1` and add its models as custom models. Gets `developer` messages as `system` messages and the end user's id as `user`. An app's thinking turned on or off reaches the model as `thinking: {"type": …}`, and a model's thinking reaches apps in every format, from `reasoning_content`. Qianfan doesn't document whether it refuses fields it doesn't know, so Kaeso refuses the ones its reference leaves out, such as `logprobs`, `store` and `web_search_options`, and estimates token counts, which Qianfan doesn't serve. Qianfan's own `web_search` reaches it from a Chat app as written. A key bound to an app of its own may need Qianfan's `appid` header, which Kaeso doesn't send; tick the default app on the key instead. **Check availability** reads Qianfan's model listing, which needs a key; a model it leaves out, such as a deployed service, is inconclusive, not unavailable. DeepSeek and ERNIE 5.5 Flash prices are Qianfan's peak prices; off-peak costs half.
- **Baseten.** Baseten Model APIs, the shared endpoint of models Baseten hosts, such as `zai-org/GLM-5.3`, `moonshotai/Kimi-K3` and `deepseek-ai/DeepSeek-V4.1-Flash-1017`; a dedicated deployment has its own address and is a [custom provider](../console/custom-providers.md). Model ids name the model's maker, and some start with another provider's id, such as `openai/gpt-oss-120b`, so call them as `baseten/openai/gpt-oss-120b` ([how a request names a model](../console/models-and-aliases.md#how-a-request-names-a-model)). Gets every app's output limit as `max_tokens`, `developer` messages as `system` messages and the end user's id as `user`. A model's thinking reaches apps in every format, from `reasoning_content`, and goes back to Baseten there on later turns, as Beam requires; GLM 5.2 and Nemotron 3 Ultra think only with `chat_template_args`, which only a Chat app can send. Kaeso calls Chat Completions only: Baseten's Messages endpoint takes no thinking or images, and Model APIs serve no embeddings, images or audio.
- **Cartesia.** Cartesia's Sonic voices and Ink Whisper transcription, called in Cartesia's own format with the key in `X-API-Key` and the API version `2026-08-14` in `Cartesia-Version`. Cartesia writes no text, so it serves the [Audio API](../api/audio.md), not chat. Voices go by their Cartesia id; a name such as `alloy` reaches Cartesia, which answers that it has no such voice. Speech comes as mp3, wav or pcm; `opus`, `aac` and `flac` are refused. Cartesia's batch transcription doesn't detect the language, so Kaeso refuses a transcription without `language`. **Check availability** reads one voice, which shows only that the key works: Cartesia lists no models. Prices are the Pro plan's overage price per credit; larger plans pay less ([Cartesia](../development/kpp/cartesia.md)).
- **Cerebras.** Cerebras Inference, with models such as `gpt-oss-120b` and `qwen-3.8-27b`. Gets `developer` messages as `system` messages, the end user's id as `user`, the text of a system message that Claude Code or Codex sends after the first turn in the next user turn, and a function without parameters with an empty parameter schema. Grok CLI's replayed `reasoning_content` reaches it as `reasoning`. It refuses a conversation that ends with an assistant message, because Cerebras answers it anew, and a `refusal` on an assistant message. Cerebras answers any field it doesn't know, such as `store`, with 400, and takes images only as data URIs. A model's thinking reaches apps in every format; `gpt-oss-120b` thinks at `reasoning_effort` `low`, `medium` or `high`, `qwen-3.8-27b` also at `none`, and Kaeso refuses other levels.
- **Cloudflare AI Gateway.** Cloudflare's REST API, which serves third-party models such as `anthropic/claude-sonnet-5.5` and `openai/gpt-6-luna`, paid with Cloudflare's Unified Billing credits or the provider keys stored on the gateway, and Workers AI models such as `@cf/zai-org/glm-4.7-flash`, billed through Workers AI. A key is a Cloudflare API token with **Workers AI Read**, and names the account it calls and, optionally, the gateway its requests go through; without a gateway, third-party models go through the account's `default` gateway, which Cloudflare creates on the first such request, and Workers AI models are called directly ([provider keys](../console/provider-keys.md#cloudflare-ai-gateway-keys)). So a key without a gateway is how you call Workers AI alone. Kaeso sends each model in the format Cloudflare lists for it: Claude models as Messages, the models Cloudflare serves only through Responses as Responses, and every other model as Chat Completions. A gateway's aliases (`custom/…`) and dynamic routes (`dynamic/…`) are added as custom models; a dynamic route takes Chat Completions only. Workers AI's embeddings models, such as `@cf/baai/bge-m3` and `@cf/qwen/qwen3-embedding-0.6b`, serve `/v1/embeddings`; Kaeso refuses `dimensions`, which they ignore, and estimates their usage, which Cloudflare doesn't report. **Check availability** finds Workers AI models in Cloudflare's model search; whether Cloudflare serves another model takes a request it bills, so the check confirms the key and its account and calls the model inconclusive. Workers AI models take images as base64 data, not as links, and some accept only some reasoning efforts, which the catalogue lists. Each request's log names Cloudflare's log entry as its upstream request. Cloudflare's Clef models answer [decisions](../api/decisions.md) in any decision format; Kaeso sends them as System One to Workers AI's `/ai/run/@cf/cloudflare/{model}`.
- **Cohere.** Cohere's [Compatibility API](https://docs.cohere.com/docs/compatibility-api), which covers part of Cohere's own API: documents, citations and rerank aren't reachable through it. Cohere refuses some fields, such as `logit_bias` and `parallel_tool_calls: false`, and gets a single `stop` string as a list. Its reasoning models think at `reasoning_effort` `none` or `high` only. Its Embed models, such as `embed-v4.0`, aren't in KPMR: add them as custom models that send as Embeddings, with their price.
- **Deepgram.** Deepgram's pre-recorded speech to text, `nova-3` and `whisper-large`, and its Aura voices, `aura-2` and `aura`, called in Deepgram's own API with the key as `Authorization: Token`. Deepgram writes no text, so it serves the [Audio API](../api/audio.md), not chat. The voice goes in `voice` and becomes Deepgram's model: `aura-2` with `thalia` is `aura-2-thalia-en`. Kaeso has Deepgram detect the language when the app names none, and reads the characters Deepgram bills from its `dg-char-count` header. Deepgram lists its models without checking the key, so **Check availability** can't spot a wrong key. For processing in the EU, Australia or India, set its [base URL](../self-hosting/configuration.md#provider-settings) to `https://api.eu.deepgram.com`, `https://api.au.deepgram.com` or `https://api.in.deepgram.com`, with the same key; Whisper runs only on the default host. Kaeso sends no `mip_opt_out`, so Deepgram's Model Improvement Program applies as it does to any request without it.
- **DeepInfra.** DeepInfra's serverless open models, such as `deepseek-ai/DeepSeek-V4-Flash-0731`, `openai/gpt-oss-120b` and `Qwen/Qwen3.8-27B`, and its embeddings models, such as `BAAI/bge-m3` and `Qwen/Qwen3-Embedding-8B`, which serve `/v1/embeddings`. A provider key needs the `inference` scope, which every new key has. Model ids name the model's maker, and some start with another provider's id, such as `openai/gpt-oss-120b`, so call them as `deepinfra/openai/gpt-oss-120b` ([how a request names a model](../console/models-and-aliases.md#how-a-request-names-a-model)). Gets every app's output limit as `max_tokens`, `developer` messages as `system` messages, the end user's id as `user`, and video as `video_url` parts for the models that take video. A model's thinking reaches apps in every format, from `reasoning_content`. Kaeso refuses the fields DeepInfra's API leaves out and would drop without a word, such as `logit_bias`, `top_logprobs` and `store`, and estimates token counts from other apps than Anthropic's, which DeepInfra counts only at its Messages API. DeepInfra lists its models without checking the key, so **Check availability** can't spot a wrong key; the first request with it reports the refused key. Its images, speech, transcriptions and videos aren't in KPMR yet.
- **DeepSeek.** Gets `developer` messages as `system` messages. Kaeso refuses an Anthropic app's `container` and `mcp_servers`, which DeepSeek ignores.
- **fal.** fal's queue for hosted image and video models, called in fal's own format with the key as `Authorization: Key …`. fal writes no text, so it serves the [Images API](../api/images.md) and the [Videos API](../api/videos.md), not chat. Every model has its own input, so Kaeso maps only FLUX.1 [dev] and [schnell], FLUX1.1 [pro], Seedream 5.5 and its edit, Veo 3.1, Kling 4 and Wan 3.0, and refuses fal's other models ([fal](../development/kpp/fal.md)). Kaeso follows the status and result URLs fal returns only on fal's queue hosts, and asks fal not to keep a request's input and output. A video needs `seconds`, which fal bills. fal's queue answers a model it doesn't know before it checks the key, so **Check availability** can't confirm a model or spot a wrong key; the first request reports either.
- **Fireworks AI.** Fireworks AI's serverless open models, such as `accounts/fireworks/models/glm-5p3-flash` and `accounts/fireworks/models/kimi-k3`, called by their full resource names (`fireworks-ai/accounts/fireworks/models/kimi-k3`) at `https://api.fireworks.ai/inference`. Kaeso calls Chat Completions by default; a model's **Sends as** value can choose Messages, Fireworks' Anthropic-compatible endpoint. Gets the end user's id as `user`, and video as `video_url` parts for the models that take video. A model's thinking reaches apps in every format, from `reasoning_content`, and goes back to Fireworks there. Fireworks lowers a `max_tokens` that doesn't fit the context window instead of refusing it, unless a Chat app sends `context_length_exceeded_behavior: "error"`. - **StepFun.** StepFun's global API, with its Step models such as `step-5-preview`, `step-3.7-flash` and `step-3.5-flash`. For the China service, which KPMR lists as `stepfun`, set StepFun's [base URL](../self-hosting/configuration.md#provider-settings) to `https://api.stepfun.com` and use a key from there; an install reaches one of them, and the catalogue keeps the global service's prices in USD. Gets every app's output limit as `max_tokens`, `developer` messages as `system` messages and video as `video_url` parts for the models that take video, and leaves out the end user's id and a Responses app's prompt cache key, which StepFun's API doesn't take; StepFun caches prompts by itself. A model's thinking reaches apps in every format, from `reasoning` or `reasoning_content`. StepFun's reasoning models always think: `reasoning_effort` takes `low`, `medium` or `high`, `low` or `high` only on `step-3.5-flash` and `step-3.5-flash-2603`, and Kaeso refuses other levels. Kaeso refuses the fields StepFun's API reference leaves out, such as `presence_penalty`, `seed`, `logprobs` and `store`, and estimates token counts, which StepFun serves only in a format of its own. Its speech and transcription models aren't served through Kaeso yet.
- **Tencent TokenHub.** Tencent Cloud's model platform, with Tencent's Hy models, such as `hy4`, `hy3` and the translation models `hy-mt2-*`, models of other makers, such as `deepseek-v4-pro`, `glm-5.3`, `kimi-k3` and `minimax-m3`, and the embeddings models `kinfra-text-embedding-0.6b` and `kinfra-text-embedding-4b`, which serve `/v1/embeddings` at their fixed size, so Kaeso refuses `dimensions`. Kaeso calls the Guangzhou region, which runs requests in mainland China. For another region, set TokenHub's [base URL](../self-hosting/configuration.md#provider-settings) and use a key made for that region: `https://tokenhub-intl.tencentmaas.com` for Singapore, and for an account on Tencent Cloud's international site `https://tokenhub-intl.tencentcloudmaas.com` (Singapore), `https://tokenhub.tencentcloudmaas.com` (Guangzhou) or `https://tokenhub-us.tencentcloudmaas.com` (Silicon Valley); a key works only in its own region and site, and an install reaches one of them. A model must be activated in TokenHub's console before a key can call it. Some ids start with another provider's id, such as `deepseek/deepseek-v4-pro`, so call them as `tencent-tokenhub/deepseek/deepseek-v4-pro` ([how a request names a model](../console/models-and-aliases.md#how-a-request-names-a-model)). Gets `developer` messages as `system` messages and video as `video_url` parts for the models that take video. A model's thinking reaches apps in every format, from `reasoning_content`. Hy4 thinks at `reasoning_effort` `high` and Hy3 at `low` or `high`; TokenHub turns their thinking off with a level of its own, `no_think`, which Kaeso doesn't send, so an app that turns thinking off gets their lowest level, as for [models that always reason](../development/kpp/reasoning.md#models-that-always-reason). TokenHub ignores fields it doesn't know without a word, so Kaeso refuses the ones its reference leaves out, such as `logit_bias`, `store` and `service_tier`, and estimates token counts, which TokenHub doesn't serve. DeepSeek models cost twice as much on weekdays during Beijing working hours; the catalogue lists that peak price. TokenHub's multimodal embeddings, images, videos and speech use formats of its own and aren't used.
- **TypeSafe.** TypeSafe's System One models, Jev 1.14 (`jev-1.14.0`) and Jev 1.13 (`jev-1.13.0`), with the aliases `jev-latest` and `jev-preview`. They answer decision questions and write no text, so they serve the [Decisions API](../api/decisions.md) in every decision format, not chat. Kaeso sends each request to TypeSafe's `/v1/systemone`, with images as `assets` and an app's uploaded images as parts again. A request with an image or a box question gets `TypeSafe-Danger-Zone-Images: true`. Kaeso also sends `TypeSafe-Danger-Zone-Long-Context: true` when it estimates the state and every question above 64k tokens, or the state and any one question above 32k. It counts 4 bytes of text a token and leaves images out, and `kaeso-adapted` names the header as `long_context`. Long context costs the same, but TypeSafe refuses a longer request without it. Box questions need Jev 1.14, and output tokens are free. A key TypeSafe doesn't know (401) and a request without a key (403) reach apps as a refused provider key. **Check availability** reads TypeSafe's model listing, which names models and aliases in a shape of its own; a model it leaves out is inconclusive, not unavailable.
- **Upstage.** Upstage's Solar models, `solar-pro4` and `solar-mini4`, aliases of dated snapshots such as `solar-pro4-260806`, which replies name, and its embeddings models `solar-embedding-2-query` and `solar-embedding-2-passage`, which serve `/v1/embeddings`: embed questions with the `-query` model and the documents they search with the `-passage` one; their vectors have 1,024 dimensions, so Kaeso refuses `dimensions`. Gets every app's output limit as `max_tokens` and `developer` messages as `system` messages, and leaves out the end user's id, which Upstage's API doesn't take. Solar models think only when an app asks: a reasoning effort from `low` to `max` turns thinking on, and it reaches apps in every format, from `reasoning`. Kaeso refuses the fields Upstage's API reference doesn't list, such as `stop` (an Anthropic app's `stop_sequences`), `seed` and `logit_bias`, and estimates token counts, which Upstage leaves to its published tokenizer. Upstage's model listing needs a valid key and isn't documented, so **Check availability** calls a model it leaves out inconclusive, not unavailable. For the Korea region, in closed beta, set Upstage's [base URL](../self-hosting/configuration.md#provider-settings) to `https://kr.api.upstage.ai`; it serves `solar-mini4` only.

Venice adds a system prompt of its own to every request unless told not to, so Kaeso adds `include_venice_system_prompt: false` to `venice_parameters` unless a Chat Completions app sets that key itself; the app's other `venice_parameters` reach Venice as written. Leaves out the end user's id, which Venice discards. A model's thinking reaches apps in every format, from `reasoning_content`. Venice refuses fields it doesn't know with an error of its own; Kaeso refuses `store` and `metadata`, which Venice takes without acting on them, and estimates token counts, which it doesn't offer. Venice's model listing names only its text models, so **Check availability** calls an embeddings model inconclusive, not unavailable. KPMR leaves out the `e2ee-*` models, which need encryption in the app.
- **Vercel.** Vercel AI Gateway, another gateway whose own routing and fallbacks run behind Kaeso. Model ids name the model's maker, such as `openai/gpt-5-nano`. Call them as `vercel/openai/gpt-5-nano`, so they never reach the maker's own provider ([how a request names a model](../console/models-and-aliases.md#how-a-request-names-a-model)). A model's **Sends as** value can choose Responses or Messages, which Vercel serves too; on Messages, Vercel passes Anthropic's `cache_control` on to Claude models. Kaeso records costs at the catalogue's prices, not at the `usage.cost` Vercel reports, which leaves out Vercel's own surcharges. Vercel counts tokens exactly only for Claude models and estimates the rest, so Kaeso estimates token counts itself for every Vercel model. Vercel answers for a model without checking the key, so **Check availability** can't spot a wrong key; the first request with it reports the refused key. A Vercel account on the free tier can't call paid models such as Claude: Vercel answers 403, which apps get as a refused provider key, and the request log keeps Vercel's reason.
- **Volcengine Ark.** ByteDance's model platform in mainland China (火山方舟), with Doubao Seed models such as `doubao-seed-2-1-pro-260915` and other makers' models such as `deepseek-v4-1-flash-261017` and `kimi-k3-1-pro-261024`. A key belongs to one project and reaches only that project's models, each of which must be activated in Ark's console first. A request may also name an inference endpoint the account created (`ep-…`), the only way to reach a fine-tuned model or a provisioned one: add it as a [custom model](../console/models-and-aliases.md) that sends as Chat Completions, with its price. For BytePlus ModelArk, ByteDance's international service with its own keys and model ids, set Volcengine Ark's [base URL](../self-hosting/configuration.md#provider-settings) to `https://ark.ap-southeast.bytepluses.com/api/v3` and use a key from there; its models aren't in KPMR, so add them as custom models. Ark's API sits at `/api/v3`, so the base URL ends there and Kaeso leaves `/v1` out of its paths. An app's thinking turned off reaches the model as `thinking: {"type": "disabled"}`, an effort as `reasoning_effort`; a model's thinking reaches apps in every format, from `reasoning_content`, and the encrypted original newer Seed models send with it goes back with the next turn. Kaeso leaves out the end user's id, which Ark's API doesn't take, and refuses the fields it leaves out, such as `seed` and `n`, OpenAI's `service_tier` values `priority` and `scale`, and `web_search_options` keys that have no effect. Its embeddings models, which serve only a multimodal endpoint with one vector for the whole input, and token counts aren't used.
- **Voyage AI.** Voyage AI's text embeddings models, such as `voyage-4`, `voyage-4-lite` and `voyage-code-4`, which serve `/v1/embeddings`, and its rerankers, such as `rerank-3` and `rerank-3-lite`, which serve `/v1/rerank` ([Rerank API](../api/rerank.md)). MongoDB sells Voyage AI's API as Atlas's Embedding and Reranking API: create a model API key in Atlas under **AI Model APIs**, and Kaeso calls `https://ai.mongodb.com`. Gets `dimensions` as `output_dimension`, which takes 256, 512, 1024 or 2048 only, floats as no `encoding_format`, which is Voyage AI's default, and Voyage AI's own `input_type`, `truncation` and `output_dtype` as written. Voyage AI refuses fields it doesn't know, so Kaeso refuses the end user's id, other sizes and token ids as input before sending. A rerank request gets `top_n` as `top_k`; Kaeso refuses `max_tokens_per_doc`, Cohere's own fields and documents with fields beside `text`. Voyage AI serves no model listing and looks up no model without its key, so **Check availability** calls every model inconclusive and can't spot a wrong key; the first request with it reports the refused key. Its multimodal and contextualized embeddings use endpoints of their own and aren't used.
- **Z.ai.** Z.ai's Anthropic-compatible API, with GLM models such as `glm-5.3` and `glm-4.6`. Kaeso calls it in the Messages format with the key in `x-api-key`, so apps in every format reach it, and an Anthropic app's request goes as the app wrote it. Z.ai documents no list of the Anthropic fields it takes, so Kaeso sends them all and leaves any refusal to Z.ai; Z.ai caches repeated prompts on its own. Z.ai sends its own error codes: an empty balance (`1113`) reaches apps as a refused provider key instead of a rate limit, an overloaded service (`1305`) as overloaded, and a prompt that is too long (`1261`) as one, so Claude Code compacts the conversation. **Check availability** spots a wrong key; Z.ai documents no model listing, so whether it spots a model Z.ai doesn't serve is untested. Z.ai bills each call by the key's type and allows GLM Coding Plan keys only in the coding tools it names, so use a Standard API key. For mainland China, set Z.ai's [base URL](../self-hosting/configuration.md#provider-settings) to `https://open.bigmodel.cn/api/anthropic` and use a key from bigmodel.cn.
