人们可以用密码、通过邮件发送的登录链接，或通过所在组织的身份提供商（基于 OpenID Connect 的单点登录）登录控制台。三项[设置](configuration.md#登录)为整个安装分别开启或关闭每种方式：`KAESO_AUTH_PASSWORD`、`KAESO_AUTH_MAGIC_LINK` 和 `KAESO_AUTH_OIDC`。组织管理员在**安全**中连接身份提供商；参见[单点登录](../console/organizations-and-projects.md#单点登录sso)。

## 登录页

登录页通常先询问邮箱地址，再提供该地址可用的方式：密码、登录链接，以及当地址的域名属于已连接身份提供商的组织时的单点登录。

在两种情况下，登录页跳过邮箱地址，直接显示提供商的按钮：

| 情况 | 登录页显示的内容 |
| --- | --- |
| 密码和登录链接都已关闭，且只有一个组织连接了身份提供商 | 该提供商的按钮 |
| 有人打开某个组织的登录链接 `https://kaeso.example.com/sign-in?org=org_…` | 该组织的按钮；其他方式开启时，还有**改用邮箱登录** |

组织的**安全**页面会显示其登录链接。按钮文字是**使用**、管理员为提供商设置的名称和**继续**，例如**使用 Acme ID 继续**；没有名称时显示**使用 SSO 继续**。有多个组织使用单点登录且没有登录链接时，登录页会询问邮箱地址，并按其域名确定组织。

**无需点击即开始**是每个连接的选项：当登录页只提供该提供商时，或有人输入的地址只能通过该提供商登录时，它会立即把人送往提供商。但在有人退出登录之后，登录页仍会等待点击，以免提供商自己的会话让其立刻重新登录；在提供商拒绝登录之后也会等待，以便原因保持可读。

## 直接前往提供商的链接

指向 `GET /platform/v1/auth/oidc/start` 的链接会把浏览器直接送往身份提供商，适合做书签或放在内网页面上：

```text
https://kaeso.example.com/platform/v1/auth/oidc/start?org=org_01J9ZKX3M7Q2V8R4T6Y0B1C5D&next=/settings/account
```

`org` 指定组织；只有一个组织使用单点登录时可以省略。该链接只在打开它的浏览器中开始登录：网关用 Cookie 把登录流程绑定到这个浏览器，并在提供商把浏览器送回时检查 state、nonce 和 PKCE verifier。最终登录的是在提供商处登录的那个人，因此放在其他网站上的链接无法让任何人登录到别人的账户，链接也不需要 `Origin` 请求头。任何问题都会回到登录页并说明原因。

## 返回正确的页面

没有会话的人打开控制台页面时，会带着该页面（放在 `next` 中）来到登录页，登录后回到该页面，经由身份提供商登录也是如此。网关把 `next` 与登录流程一起保存，从不放进提供商的 URL。只有本安装控制台的路径才有效：以 `//` 或反斜杠开头、指向其他网站、包含换行符，或指向 Platform API 或模型 API 的值都会被忽略，改为打开首页。登录失败时，无论是在提供商处还是之后，登录页都会为下次尝试保留 `next`。如果登录是从某个组织的登录链接或按钮开始的，登录页还会保留该组织，在显示原因的同时再次显示该组织的按钮。

## 谁可以通过单点登录登录

- 只有连接所配置的邮箱域名下的地址。在一个安装中，每个域名只属于一个组织。
- 只有提供商未标记为未验证的地址。
- 首次使用 Kaeso 的人，以组织为未受邀者设定的角色加入，或凭发给其地址的邀请加入；两者都没有时，不获得任何访问权限。
- 已有账户只能在自己已是成员的组织中通过单点登录登录。要接受邀请，需先用其他方式登录。
- 其他域名的地址（例如公共邮箱服务商的地址）无法通过组织的提供商登录，即使有邀请也不行。在关闭了密码和登录链接的安装上，这样的人无法登录。不要为绕过这一点而把公共邮箱服务商的域名加入连接：那样该域名下的每个地址都会通过自己的提供商登录，其他组织也无法再使用该域名。

## 没有密码的安装

要只使用单点登录，关闭其他方式：

```yaml
services:
  gateway:
    environment:
      KAESO_AUTH_PASSWORD: "false"
      KAESO_AUTH_MAGIC_LINK: "false"
```

这样设置页面不会要求密码，第一个管理员也永远不会有密码。设置完成后会打开组织的**安全**页面，以便在同一会话中连接身份提供商。请给第一个管理员一个属于该连接某个域名的地址，以便之后通过它登录。

在连接可用之前，不要开启**要求单点登录**：在这样的安装上它没有额外作用，而要求单点登录的组织会拒绝其他所有会话，包括运维人员登录链接产生的会话。

## 重新登录

当所有方式都无法登录时（身份提供商宕机或配置错误，或设置会话在单点登录可用之前就已结束），在服务器上为现有账户输出一次性登录链接：

```bash
docker compose exec gateway kaeso user sign-in-link owner@example.com
```

该链接在 15 分钟内可使用一次，即使通过邮件发送的登录链接已关闭也有效，因此永远不必重新开启密码。任何拿到它的人都能以该用户身份登录：它只输出在终端中，从不记录到日志或发送出去，审计日志会将其记录为 `user.sign_in_link`。已停用的账户得不到链接，需先重新启用。
