用户可以用密码、邮件中的登录链接，或通过所在组织的身份提供商（OpenID Connect）登录控制台。两项[登录设置](configuration.md#登录)为整个实例开启或关闭密码和登录链接。单点登录按组织设置，而不是按实例设置：任何组织的管理员都可以在组织的**安全**页面上连接其身份提供商（[组织和项目](../console/organizations-and-projects.md)）。

## 登录页

登录页总是先询问邮箱地址。然后它会提供适用于该地址的方式：密码、登录链接和单点登录。地址属于某个已配置身份提供商的组织的已验证邮箱域名时，单点登录适用于该地址（[验证邮箱域名](../console/organizations-and-projects.md#验证邮箱域名)）。对于其他域名的地址，或其组织尚未验证的域名的地址，登录页从不提供单点登录。

按钮文字为“使用 {名称} 继续”，名称由管理员为身份提供商设定；没有名称时显示**使用 SSO 继续**。当单点登录是该地址唯一的登录方式，且连接开启了**无需点击即开始**时，页面会跳过按钮。输入地址后，页面会直接前往身份提供商。用户退出登录后，或身份提供商拒绝了一次登录时，页面会重新询问地址并显示原因。

登录页只在输入地址后提供单点登录，也没有任何链接能为某个组织启动它。因此，其他网站上的链接无法让浏览器经由身份提供商登录到别人的账户。如需书签或内网页面，请链接到登录页，例如 `https://kaeso.example.com/sign-in`。开启**无需点击即开始**后，成员输入地址后即会前往身份提供商。

单点登录也从不替换另一个账户的会话。如果浏览器已登录，而身份提供商返回的是另一个账户，浏览器保持登录，页面提示 `signed_in_as_other`。如需切换账户，请先退出登录。

登录后，用户会回到最初打开的控制台页面，经由身份提供商登录也是如此。

## 近期登录

当某个操作需要近期登录时，控制台会按照 OpenID Connect 的规定，请身份提供商重新登录该用户（`prompt=login`、`max_age=0`）。只有表明用户在本次确认期间登录的答复才算数，因此一次确认总是意味着一次新的登录。

身份提供商也可能不经询问，直接用它自己较早的会话让用户登录。因此，来自单点登录的会话从身份提供商的 `auth_time` 算起，而不是从回到 Kaeso 的时间算起。只有当该时间在 15 分钟以内时，它才算作近期登录。

Kaeso 用令牌的签发时间 `iat` 来衡量它，两者都来自身份提供商的时钟，所以两台服务器的时钟不必一致。没有 `auth_time` 时，会话从一开始就被视为早于 15 分钟。

有些身份提供商无法确认近期登录：它们省略 `auth_time`，或者忽略 `max_age=0`，用自己较早的登录作答。OpenID Connect 规定，请求中带有 `max_age` 时必须重新登录并发送 `auth_time`，但在一次确认失败之前，Kaeso 无法分辨忽略这一点的身份提供商。因此，只有当账户没有其他方式时（没有密码、没有登录链接，也没有设置密码的链接），控制台才提供用单点登录确认。

Kaeso 会以 `cannot_confirm` 拒绝没有新登录的确认，并在连接上记下该身份提供商无法确认。此后控制台不再提供它，组织的**安全**页面会显示**近期登录**。对于其组织要求单点登录的账户（见[受管理的账户](#受管理的账户)），没有其他方式可以确认，因此它无法执行需要近期登录的操作。颁发者或客户端 ID 更改时，Kaeso 会忘记此记录；其他登录不会留下记录，因为请求中没有 `max_age` 时，身份提供商可以沿用自己的登录。

## 谁可以通过单点登录登录

- 只有连接中已验证邮箱域名下的地址（见[验证邮箱域名](../console/organizations-and-projects.md#验证邮箱域名)）。在一个实例中，每个域名只能由一个组织验证。
- 只有身份提供商通过 `email_verified` 标记为已验证的地址。对于从不发送该声明的身份提供商，连接可以关闭**要求已验证的地址**；被标记为未验证的地址仍会被拒绝。
- Kaeso 新用户凭发往其地址的邀请加入组织，或获得连接为无邀请者设定的角色。两者都没有时，无法获得访问权限。即使[账户创建设置](../console/instance-administration.md#更改实例设置)不允许注册，Kaeso 也会创建其账户，因为组织的身份提供商为其担保。
- Kaeso 会把每个账户与其在身份提供商处的身份（身份提供商的 issuer 和 subject）关联。之后的登录依据这个关联，而不是邮箱地址。
- 已有账户只能登录其已是成员的组织，并且要等所有者关联后才能通过单点登录登录。所有者需先用其他方式登录，再在**账户** › **安全**中关联（见[关联单点登录](../console/account.md#关联单点登录)）。要接受邀请，该账户需先用其他方式登录。
- 其他域名下的地址（例如公共邮箱服务商的地址）无法通过组织的身份提供商登录，即使有邀请也不行。

通过身份提供商登录后能打开什么，取决于其组织是否管理该账户（见[受管理的账户](#受管理的账户)）。

连接中不能包含公共邮箱服务商的域名（例如 `gmail.com`）：否则该域名下的每个地址都会通过某一个组织的身份提供商登录。

## 受管理的账户

启用单点登录的组织管理其已验证邮箱域名下的账户。Kaeso 在每次请求时都根据账户的地址判断这一点，因此地址变更、域名失去验证或连接被移除，都会立即改变结果。每个域名只能由一个组织验证，因此一个账户最多由一个组织管理。组织的其他成员是访客：他们属于该组织，但地址在其他域名下。

受管理的账户通过其组织的身份提供商登录是一次完整登录，就像工作账户属于某家公司一样。它可以打开此人所属的每个组织（各自适用自己的要求），也可以更改账户。通过不管理该账户的组织的身份提供商登录，只能打开该组织。地址在其他域名下时就会如此，例如地址更改之后，或该域名不再经过验证时。

| | 受管理的账户，通过其组织的身份提供商 | 通过其他组织的身份提供商 | 密码或登录链接 |
| --- | --- | --- | --- |
| 组织 | 此人所属的每个组织 | 仅该身份提供商所属的组织 | 每个组织，但管理该账户且要求单点登录的组织除外 |
| 组织的双重验证要求 | 由身份提供商满足 | 在该身份提供商所属的组织中满足 | 需要验证码 |
| 账户更改 | 允许，需近期登录 | 需要密码或登录链接 | 允许，需近期登录 |
| 实例管理 | 仅通过为实例管理员选定的组织 | 需要密码或登录链接 | 实例管理员可以使用 |

受管理的账户的地址由身份提供商掌管。`POST me/email` 会以 `Your organization manages this address; change it at its identity provider.` 拒绝更改，确认此前更改的链接也不再有效。

当通过身份提供商登录时带来该组织某个已验证域名下的另一个地址，Kaeso 会把账户的地址改为该地址。这是因为关联账户的是 issuer 和 subject，而不是地址。组织的审计日志会以 `user.email_change` 记录此次更改。Kaeso 绝不会占用其他账户已在使用的地址，不管理该账户的组织的身份提供商也绝不会更改它。

**账户** › **个人资料**会显示**管理方**和组织名称，组织的**成员**页面会标出访客（见[通过单点登录登录之后](../console/account.md#通过单点登录登录之后)）。

### 要求单点登录

开启**要求单点登录**后，组织管理的账户在整个实例上都只能通过其身份提供商登录。登录页只向这些账户提供该身份提供商。Kaeso 会拒绝密码、登录链接、注册或没有账户的邀请，并显示 `Your organization requires single sign-on; continue with its identity provider.`

开启该要求会结束这些账户通过密码或登录链接建立的会话（开启该要求的会话除外）。在要求开启期间验证另一个域名也会如此。

访客保留自己的登录方式，并用它打开该组织，同时须满足该组织的双重验证要求。服务器上生成的登录链接仍然可以让受管理的账户登录（见[重新登录](#重新登录)）。

### 实例管理员

默认情况下，任何组织的身份提供商都不能管理实例，因此组织的身份提供商管理员无法把自己变成实例管理员。如需允许，请在**实例** › **常规** › **实例管理员的单点登录**下选择该组织（见[更改实例设置](../console/instance-administration.md#更改实例设置)）。此后，只要该组织管理实例管理员的账户，实例管理员通过该组织身份提供商的登录即可管理实例。

选择该组织需要实例管理员使用密码或登录链接进行的近期登录，不能通过单点登录。实例审计日志会以 `instance.admin_sso_update` 记录此次选择。只能选择已连接身份提供商的组织。如果该组织之后失去连接，此设置不再生效，**常规**会说明这一点。

如果没有实例管理员能以这种方式登录，运维人员可以改在服务器上按 ID 选择该组织。规则和审计记录都相同，`none` 表示不选：

```bash
docker compose exec gateway kaeso instance admin-sso org_…
```

## 不用密码和登录链接运行

要让用户只能通过组织的身份提供商登录，请在首次启动前关闭密码和登录链接：

```yaml title="compose.override.yaml"
services:
  gateway:
    environment:
      KAESO_AUTH_PASSWORD: "false"
      KAESO_AUTH_MAGIC_LINK: "false"
```

1. 为第一个管理员选用身份提供商将会覆盖的域名下的地址，以便之后通过它登录。
2. 打开设置链接。设置页不会要求设置密码，完成后会打开组织的**安全**页面。
3. 在同一会话中连接身份提供商。
4. 在**账户** › **安全**下，选择组织旁的**关联**，并在身份提供商处登录。这样既关联了您的账户，也确认了连接可以正常使用。

登录页仍会先询问邮箱地址，并提供其组织的身份提供商。不属于任何组织已验证域名的地址无法登录，页面会说明这一点。

只有在实例管理员为此选定组织后，通过单点登录登录的会话才能管理实例（见[实例管理员](#实例管理员)）。在此之前，要管理实例，请使用服务器上生成的[一次性登录链接](#重新登录)登录。

> [!IMPORTANT]
> 在连接确认可用之前，不要开启**要求单点登录**。在没有密码的实例上，它没有任何额外作用。它还会让该组织拒绝其管理的账户所有并非来自其身份提供商的会话，包括通过运维人员的登录链接建立的会话。

## 重新登录

当所有登录方式都失效时，在服务器上为已有账户打印一个一次性登录链接。身份提供商宕机或配置错误，或设置会话在单点登录生效前就已结束时，这个方法都能派上用场：

```bash
docker compose exec gateway kaeso user sign-in-link owner@example.com
```

该链接仅可使用一次，15 分钟内有效，即使邮件登录链接已关闭也能使用，因此永远不必重新开启密码登录。任何拿到链接的人都能以该用户身份登录。Kaeso 只在您的终端中打印它，从不记录或发送。审计日志会以 `user.sign_in_link` 记录此事。

已停用的账户在重新启用前无法获得链接。开启双重验证时，该链接也会要求输入验证码。如果此人丢失了身份验证器，请先用 `kaeso user reset-2fa` 移除双重验证。

即使管理该账户的组织要求单点登录，该链接也能让受管理的账户登录。这个会话可以打开此人的账户、其所属的其他组织，如果此人是实例管理员，还可以打开实例管理；要求单点登录的那个组织仍对它关闭。
