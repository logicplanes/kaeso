用户可以用密码、邮件中的登录链接，或通过所在组织的身份提供商（OpenID Connect）登录控制台。两项[登录设置](configuration.md#登录)为整个实例开启或关闭密码和登录链接。单点登录按组织设置，而不是按实例设置：组织管理员在组织的**安全**页面上连接身份提供商后，它就对该组织生效（[组织和项目](../console/organizations-and-projects.md)），每个组织都可以这样做。

## 登录页

登录页总是先询问邮箱地址，然后提供适用于该地址的方式：密码、登录链接，以及在该地址属于某个已配置身份提供商的组织的已验证邮箱域名时，提供单点登录（[验证邮箱域名](../console/organizations-and-projects.md#验证邮箱域名)）。其他域名的地址，或其组织尚未验证的域名的地址，永远不会被提供单点登录。

按钮文字为“使用 {名称} 继续”，名称由管理员为身份提供商设定；没有名称时显示**使用 SSO 继续**。当单点登录是该地址唯一的登录方式，且连接开启了**无需点击即开始**时，页面会在输入地址后直接前往身份提供商，不再显示按钮。用户退出登录后，或身份提供商拒绝了一次登录时，页面会重新询问地址并显示原因。

单点登录只在输入地址后提供：没有任何链接能为某个组织启动它，因此其他网站上的链接无法让浏览器经由身份提供商登录到别人的账户。如需书签或内网页面，请链接到登录页，例如 `https://kaeso.example.com/sign-in`；开启**无需点击即开始**后，成员输入地址后即会前往身份提供商。

单点登录也从不替换另一个账户的会话。如果浏览器已登录，而身份提供商返回的是另一个账户，浏览器保持登录，页面提示 `signed_in_as_other`；如需切换账户，请先退出登录。

登录后，用户会回到最初打开的控制台页面，经由身份提供商登录也是如此。

## 近期登录

当某个操作需要近期登录时，控制台会按照 OpenID Connect 的规定，请身份提供商重新登录该用户（`prompt=login`、`max_age=0`）。如果身份提供商的答复表明上次登录早于这次请求，则以 `stale_sign_in` 拒绝，因此一次确认总是意味着一次新的登录。

身份提供商也可能不经询问，直接用它自己较早的会话让用户登录。因此，来自单点登录的会话从身份提供商的 `auth_time` 算起，而不是从回到 Kaeso 的时间算起；只有当该时间在 15 分钟以内时，才算作近期登录。Kaeso 用令牌的签发时间 `iat` 来衡量它，两者都来自身份提供商的时钟，所以两台服务器的时钟不必一致。没有 `auth_time` 时，会话从一开始就被视为早于 15 分钟。

因此，单点登录要能确认近期登录，身份提供商必须在 ID 令牌中发送登录时间 `auth_time`。OpenID Connect 规定，请求中带有 `max_age` 时必须发送它，但有些身份提供商从不发送。没有 `auth_time` 的答复会以 `no_auth_time` 拒绝，Kaeso 会在连接上记下该身份提供商无法确认。此后控制台在请用户重新登录时不再提供该身份提供商，而是提供密码、登录链接或设置密码的链接。

对于其组织要求单点登录的账户（见[受管理的账户](#受管理的账户)），没有其他方式可以确认，因此它无法执行需要近期登录的操作。组织的**安全**页面会在**近期登录**下说明这两种情况。一旦该身份提供商的某个 ID 令牌带有 `auth_time`，Kaeso 就会再次提供它；颁发者或客户端 ID 更改时，Kaeso 会忘记此前的记录。没有 `auth_time` 的登录不会留下记录，因为请求中没有 `max_age` 时，身份提供商可以省略它。

## 谁可以通过单点登录登录

- 只有连接中已验证邮箱域名下的地址（见[验证邮箱域名](../console/organizations-and-projects.md#验证邮箱域名)）。在一个实例中，每个域名只能由一个组织验证。
- 只有身份提供商通过 `email_verified` 标记为已验证的地址。对于从不发送该声明的身份提供商，连接可以关闭**要求已验证的地址**；被标记为未验证的地址仍会被拒绝。
- Kaeso 新用户凭发往其地址的邀请加入组织，或获得连接为无邀请者设定的角色。两者都没有时，无法获得访问权限。即使[账户创建设置](../console/instance-administration.md#更改实例设置)不允许注册，Kaeso 也会创建其账户，因为组织的身份提供商为其担保。
- Kaeso 会把每个账户与其在身份提供商处的身份（身份提供商的 issuer 和 subject）关联。之后的登录依据这个关联，而不是邮箱地址。
- 已有账户只有在其所有者用其他方式登录、并在**账户** › **安全**中关联后（见[关联单点登录](../console/account.md#关联单点登录)），才能通过单点登录登录，而且只能登录其已是成员的组织。要接受邀请，需先用其他方式登录。
- 其他域名下的地址（例如公共邮箱服务商的地址）无法通过组织的身份提供商登录，即使有邀请也不行。

通过身份提供商登录后能打开什么，取决于其组织是否管理该账户（见[受管理的账户](#受管理的账户)）。

连接中不能包含公共邮箱服务商的域名（例如 `gmail.com`）：否则该域名下的每个地址都会通过某一个组织的身份提供商登录。

## 受管理的账户

启用单点登录的组织管理其已验证邮箱域名下的账户。Kaeso 在每次请求时都根据账户的地址判断这一点，因此地址变更、域名失去验证或连接被移除，都会立即改变结果。每个域名只能由一个组织验证，因此一个账户最多由一个组织管理。组织的其他成员是访客：他们属于该组织，但地址在其他域名下。

受管理的账户通过其组织的身份提供商登录是一次完整登录，就像工作账户属于某家公司一样。它可以打开此人所属的每个组织（各自适用自己的要求），也可以更改账户。通过不管理该账户的组织的身份提供商登录，只能打开该组织。地址在其他域名下时就会如此，例如地址更改之后，或该域名不再经过验证时。

| | 受管理的账户，通过其组织的身份提供商 | 通过其他组织的身份提供商 | 密码或登录链接 |
| --- | --- | --- | --- |
| 组织 | 此人所属的每个组织 | 仅该身份提供商所属的组织 | 每个组织，但管理该账户且要求单点登录的组织除外 |
| 组织的双重验证要求 | 由身份提供商满足 | 在该身份提供商所属的组织中满足 | 需要验证码 |
| 账户更改 | 允许，需近期登录 | 需要密码或登录链接 | 允许，需近期登录 |
| 实例管理 | 需要密码或登录链接 | 需要密码或登录链接 | 实例管理员可以使用 |

**账户** › **个人资料**会显示**管理方**和组织名称，组织的**成员**页面会标出访客（见[通过单点登录登录之后](../console/account.md#通过单点登录登录之后)）。

### 要求单点登录

开启**要求单点登录**后，组织管理的账户在整个实例上都只能通过其身份提供商登录。登录页只向这些账户提供该身份提供商；密码、登录链接、注册或没有账户的邀请都会被拒绝，并显示 `Your organization requires single sign-on; continue with its identity provider.` 开启该要求会结束这些账户通过密码或登录链接建立的会话（开启该要求的会话除外）；在要求开启期间验证另一个域名也会如此。

访客保留自己的登录方式，并用它打开该组织，同时须满足该组织的双重验证要求。服务器上生成的登录链接仍然可以让受管理的账户登录（见[重新登录](#重新登录)）。

## 不用密码和登录链接运行

要让用户只能通过组织的身份提供商登录，请在首次启动前关闭密码和登录链接：

```yaml title="compose.override.yaml"
services:
  gateway:
    environment:
      KAESO_AUTH_PASSWORD: "false"
      KAESO_AUTH_MAGIC_LINK: "false"
```

1. 为第一个管理员选用身份提供商将会覆盖的域名下的地址，以便之后通过它登录。
2. 打开设置链接。设置页不会要求设置密码，完成后会打开组织的**安全**页面。
3. 在同一会话中连接身份提供商。
4. 在**账户** › **安全**下，选择组织旁的**关联**，并在身份提供商处登录。这样既关联了您的账户，也确认了连接可以正常使用。

登录页仍会先询问邮箱地址，并提供其组织的身份提供商。不属于任何组织已验证域名的地址无法登录，页面会说明这一点。

通过单点登录登录的会话无法管理实例。要管理实例，请使用服务器上生成的[一次性登录链接](#重新登录)登录。

> [!IMPORTANT]
> 在连接确认可用之前，不要开启**要求单点登录**。在没有密码的实例上，它没有任何额外作用，还会让该组织拒绝其管理的账户所有并非来自其身份提供商的会话，包括通过运维人员的登录链接建立的会话。

## 重新登录

当所有登录方式都失效时，在服务器上为已有账户打印一个一次性登录链接。身份提供商宕机或配置错误，或设置会话在单点登录生效前就已结束时，这个方法都能派上用场：

```bash
docker compose exec gateway kaeso user sign-in-link owner@example.com
```

该链接仅可使用一次，15 分钟内有效，即使邮件登录链接已关闭也能使用，因此永远不必重新开启密码登录。任何拿到链接的人都能以该用户身份登录。Kaeso 只在您的终端中打印它，从不记录或发送，审计日志会以 `user.sign_in_link` 记录此事。已停用的账户在重新启用前无法获得链接。开启双重验证时，该链接也会要求输入验证码；如果此人丢失了身份验证器，请先用 `kaeso user reset-2fa` 移除双重验证。

即使管理该账户的组织要求单点登录，该链接也能让受管理的账户登录。这个会话可以打开此人的账户、其所属的其他组织，如果此人是实例管理员，还可以打开实例管理；要求单点登录的那个组织仍对它关闭。
