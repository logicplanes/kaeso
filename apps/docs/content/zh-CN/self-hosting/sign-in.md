用户可以用密码、邮件中的登录链接，或通过所在组织的身份提供商（OpenID Connect）登录控制台。三项[登录设置](configuration.md#登录)为整个实例开启或关闭每种方式。组织管理员在组织的**安全**页面上连接身份提供商（[组织和项目](../console/organizations-and-projects.md)）。

## 登录页

登录页先询问邮箱地址，然后提供适用于该地址的方式：密码、登录链接，以及在该地址的域名属于某个已配置身份提供商的组织时，提供单点登录。

在两种情况下，登录页会直接显示某个身份提供商的按钮：

- 密码和登录链接都已关闭，且恰好有一个组织配置了身份提供商。
- 有人打开组织的登录链接，例如 `https://kaeso.example.com/sign-in?org=org_…`，该链接显示在组织的**安全**页面上。其他方式开启时，页面还会提供**改用邮箱登录**。

按钮文字为“使用 {名称} 继续”，名称由管理员为身份提供商设定；没有名称时显示**使用 SSO 继续**。开启**无需点击即开始**后，当身份提供商是用户唯一的登录方式时，页面会立即把用户送往该提供商。但在用户退出登录后，或身份提供商拒绝了一次登录时，页面仍会等待点击，以便看清原因。

登录后，用户会回到最初打开的控制台页面，经由身份提供商登录也是如此。

## 直接前往提供商的链接

指向 `/platform/v1/auth/oidc/start` 的链接会把浏览器直接送往身份提供商，适合书签或内网页面：

```text
https://kaeso.example.com/platform/v1/auth/oidc/start?org=org_01J9ZKX3M7Q2V8R4T6Y0B1C5D&next=/settings/account
```

`org` 指定组织；只有一个组织使用单点登录时可以省略。`next` 是登录后打开的控制台页面。该链接只会让打开它的浏览器登录，身份是在身份提供商处登录的那个人，所以放在其他网站上的链接无法让任何人登录到别人的账户。

## 谁可以通过单点登录登录

- 只有连接所配置邮箱域名下的地址。在一个实例中，每个域名只属于一个组织。
- 只有身份提供商没有标记为未验证的地址。
- Kaeso 新用户凭发往其地址的邀请加入组织，或获得连接为无邀请者设定的角色。两者都没有时，无法获得访问权限。
- 已有账户只能在其已是成员的组织中通过单点登录登录。要接受邀请，需先用其他方式登录。
- 其他域名下的地址（例如公共邮箱服务商的地址）无法通过组织的身份提供商登录，即使有邀请也不行。

不要为了让这类用户进入而把公共邮箱服务商的域名加入连接。否则该域名下的每个地址都会通过您的身份提供商登录，其他组织也无法再使用这个域名。

## 只用单点登录运行

要让用户只能通过身份提供商登录，请在首次启动前关闭其他方式：

```yaml title="compose.override.yaml"
services:
  gateway:
    environment:
      KAESO_AUTH_PASSWORD: "false"
      KAESO_AUTH_MAGIC_LINK: "false"
```

1. 为第一个管理员选用身份提供商将会覆盖的域名下的地址，以便之后通过它登录。
2. 打开设置链接。设置页不会要求设置密码，完成后会打开组织的**安全**页面。
3. 在同一会话中连接身份提供商，并通过它登录一次，确认可以正常使用。

> [!IMPORTANT]
> 在连接确认可用之前，不要开启**要求单点登录**。在没有密码的实例上，它没有任何额外作用，还会拒绝所有其他会话，包括通过运维人员的登录链接建立的会话。

## 重新登录

当所有登录方式都失效时，在服务器上为已有账户打印一个一次性登录链接。身份提供商宕机或配置错误，或设置会话在单点登录生效前就已结束时，这个方法都能派上用场：

```bash
docker compose exec gateway kaeso user sign-in-link owner@example.com
```

该链接仅可使用一次，15 分钟内有效，即使邮件登录链接已关闭也能使用，因此永远不必重新开启密码登录。任何拿到链接的人都能以该用户身份登录。Kaeso 只在您的终端中打印它，从不记录或发送，审计日志会以 `user.sign_in_link` 记录此事。已停用的账户在重新启用前无法获得链接。
