人员可以用密码、通过邮件发送的登录链接，或通过所在组织的身份提供商（单点登录，OpenID Connect）登录控制台。三项[设置](configuration.md#登录)可为整个安装开启或关闭每种方式：`KAESO_AUTH_PASSWORD`、`KAESO_AUTH_MAGIC_LINK` 和 `KAESO_AUTH_OIDC`。组织管理员在**安全**下连接身份提供商；参见[组织和项目](../console/organizations-and-projects.md)。

## 登录页

登录页通常先询问邮箱地址，然后提供该地址可用的方式：密码、登录链接，以及当该地址的域名属于某个已连接身份提供商的组织时的单点登录。

在两种情况下，它会跳过邮箱地址，直接显示提供商的按钮：

| 情况 | 登录页显示的内容 |
| --- | --- |
| 安装只通过单点登录登录（密码和登录链接都已关闭），并且只有一个组织连接了身份提供商 | 该提供商的按钮 |
| 有人打开某个组织的登录链接 `https://kaeso.example.com/sign-in?org=org_…` | 该组织的按钮；在其他方式开启时，还有**改用邮箱登录** |

组织的**安全**页面会显示它的登录链接。按钮显示为**使用**加管理员为提供商设置的名称再加**继续**，例如**使用 Acme ID 继续**；没有名称时显示**使用 SSO 继续**。如果有多个组织使用单点登录且没有登录链接，登录页会询问邮箱地址，并按其域名确定组织。

**无需点击即开始**是每个连接的选项：只要登录页只提供该提供商，或者有人输入的邮箱地址只能通过该提供商登录，它就会立即把人员送往提供商。在有人退出登录之后，登录页会等待点击，以免提供商自己的会话让其立即重新登录；在提供商拒绝登录之后也会等待，以便原因保持可读。

## 直接前往提供商的链接

指向 `GET /platform/v1/auth/oidc/start` 的链接会把浏览器直接送往身份提供商，适合书签或内网页面：

```text
https://kaeso.example.com/platform/v1/auth/oidc/start?org=org_01J9ZKX3M7Q2V8R4T6Y0B1C5D&next=/settings/account
```

`org` 指定组织；只要只有一个组织使用单点登录，就可以省略它。该链接只会在打开它的浏览器中开始登录：网关用一个 Cookie 把流程绑定到该浏览器，并在提供商把浏览器送回时检查 state、nonce 和 PKCE verifier。最终登录的人就是在提供商处登录的人，因此放在其他网站上的链接无法让任何人登录到别人的账户，链接也不需要 `Origin` 请求头。出现问题时会回到登录页并显示原因。

## 返回正确的页面

没有会话的人打开控制台页面时，会被送往登录页，并把该页面放在 `next` 中，登录后（包括通过身份提供商登录）会回到该页面。`next` 与登录流程一起保存在网关上，从不放进提供商的 URL。只有此安装上的控制台路径才有效：以 `//` 或反斜杠开头、指向其他网站、包含换行，或指向 Platform API 或模型 API 的值会被拒绝，并改为打开首页。当提供商拒绝某人时，登录页会为下一次尝试保留 `next`。

## 谁可以通过单点登录登录

- 只有连接所列邮箱域名下的地址才能通过它登录。在一个安装中，每个域名只属于一个组织。
- 提供商不得将该地址标记为未验证。
- 新加入 Kaeso 的人员会以组织为无邀请人员设定的角色加入，或凭发送到其地址的邀请加入；两者都没有时，就没有访问权限。
- 已有账户只能在其已是成员的组织中通过单点登录登录；要接受邀请，需要先用其他方式登录。
- 其他域名下的地址（例如公共邮箱服务商的地址）无法通过该组织的提供商登录，即使有邀请也不行。在关闭了密码和登录链接的安装上，这样的人员没有任何登录方式。不要为了绕过这一点而填写公共邮箱服务商的域名：否则该域名下的每个地址都会通过你的提供商登录，其他组织也无法再使用该域名。

## 没有密码的安装

要只用单点登录运行，请关闭其他方式：

```yaml
services:
  gateway:
    environment:
      KAESO_AUTH_PASSWORD: "false"
      KAESO_AUTH_MAGIC_LINK: "false"
```

此时设置页面不会要求密码，第一位管理员也永远不会有密码。设置完成后，它会打开组织的**安全**页面，以便在同一会话中连接身份提供商。请为第一位管理员使用连接所列域名之一下的地址，以便之后通过它登录。在这样的安装上，要求单点登录不会带来任何好处；在连接可用之前请保持关闭，因为要求单点登录的组织会拒绝其他所有会话，包括来自运维人员登录链接的会话。

## 重新登录

当没有任何登录方式可用时（例如身份提供商宕机或配置错误，或设置时的会话在单点登录可用之前就已结束），请在网关运行的地方为已有账户输出一个一次性登录链接：

```bash
docker compose exec gateway kaeso user sign-in-link owner@example.com
```

该链接只能使用一次，须在 15 分钟内使用，即使通过邮件发送的登录链接已关闭也有效，也无需重新开启密码。任何拿到它的人都可以以该人员身份登录，因此它只显示在终端中，从不写入日志或发送出去，审计日志会将其记录为 `user.sign_in_link`。

## 设置链接

安装中还没有用户时，网关日志只会说明安装尚未设置，从不包含设置链接本身：否则任何能读取日志的人都可能接管安装。`kaeso setup-link` 会输出该链接；参见[首次启动时发生的事情](installation.md#首次启动时发生的事情)。
