控制台是 `apps/console` 中的一个静态 React 应用，与网关使用同一个域名。因此它的会话 Cookie 是第一方 Cookie，也不需要 CORS；只有从浏览器调用模型 API 的 Web 应用才需要把来源加入 `KAESO_CORS_ALLOWED_ORIGINS`。除了网关设置的 HttpOnly Cookie，控制台不保存任何东西。列表、筛选条件、时间段和打开的详情都记录在地址中，因此链接可以分享，后退按钮也能正常使用。

| 部分 | 位置 |
| --- | --- |
| 路由、加载器和页面 | `src/routes`、`src/features` |
| 根据 `openapi.json` 生成类型的 Platform API 客户端及其查询 | `src/api` |
| 会话、权限和路由守卫 | `src/auth` |
| 应用框架、侧边栏、命令面板和快捷键 | `src/shell` |
| 只有控制台使用的库组件组合 | `src/kaeso` |
| 各种语言及其文案目录 | `src/i18n` |
| 控制台书写金额、时间段、标签和其他值的方式 | `src/format` |
| 生成器、各套栈、示例数据、翻译检查、预算和许可证 | `scripts` |
| 只允许布局类和要求文本翻译的 lint 规则 | `eslint` |
| 端到端测试套件 | `e2e` |
| 开发栈的模拟服务商、身份提供商、版本和主密钥 | `stack` |

## 规则

- **只使用 Platform API**，并且每次调用都通过 `src/api` 中的客户端。API 做不到的事情不显示，也不伪造任何东西。
- **权限来自 API，绝不猜测。** 组织权限来自 `auth/session`，项目权限来自 `GET …/projects/{project}/my-rights`，每项权限的名称、描述、类别和前置条件来自 `GET orgs/{org}/rights`。`403` 就是最终结论：用户无权查看的区域会被隐藏，单个操作则被停用，并显示该权限的名称以及谁能授予它（`useNeedsRight`）。
- **服务商同样来自 API。** 每个服务商的名称、密钥页面、密钥前缀和格式都来自 `GET orgs/{org}/providers`，组织的路由加载一次并保留一小时。控制台的代码中不写任何服务商，因此网关新增的服务商无需新版控制台即可出现。网关不再列出的 ID（例如旧日志中的）会显示为首字母大写的 ID。
- **浏览器中没有机密信息。** 控制台从不读取会话 Cookie，密钥的机密部分只显示一次，从不存储。`localStorage` 只保存上次所在的组织和项目、最近打开的条目、主题、语言、侧边栏的宽度和状态、请求日志的列设置，以及试验场中尚未发送的提示。`sessionStorage` 只在受邀者为接受邀请而登录期间保存邀请的令牌。链接中的其他令牌以及变更操作返回的机密信息只保存在内存中，用过之后或其对话框关闭后即被丢弃。
- **对话框每次打开都是全新的。** 对话框保存的内容（例如字段、步骤、结果或只显示一次的机密）都放在每次打开时重新挂载的组件中：放在 `DialogScope` 内，或只在对话框打开时渲染。某一行的侧滑面板绝不会显示另一行的数据。
- **链接中的令牌放在片段里。** 控制台只读取一次 `location.hash`，调用 API，然后把地址替换为不含片段的地址。
- **每个可见元素都来自 `@logicplanes/kaeso-ui`**，`className` 只包含布局：外边距、宽度、grid、flex、间距和定位。`pnpm lint` 通过 `apps/console/eslint/kaeso.js` 中的规则强制执行这一点。
- **每个词都有三种语言**，通过 `t()` 实现（[翻译](../translations.md#控制台)）。
- **描述是一句能放进一行的话。** 长度上限因位置而异：设置行 60 个字符（输入框旁边为 50），区块或页面 80 个字符（操作按钮旁边为 70），对话框 100 个字符，空状态 90 个字符，提示消息 60 个字符。`src/copy.test.ts` 检查每种语言中的设置行、区块和页面，德语和中文有 15% 的余量。

## 数据

每次读取都是一个以请求为键的 TanStack Query 查询，每次修改都是一个 mutation，它会使受影响的数据和审计日志失效。

- **客户端**：`src/api/client.ts` 是 `openapi-fetch`，使用 `pnpm --filter kaeso-console generate` 根据 `openapi.json` 写入 `src/api/generated` 的类型。控制台的 `dev`、`build`、`typecheck`、`test` 和 `e2e` 脚本会先运行生成器，生成的内容从不提交。客户端会发送会话 Cookie，并把每次失败转换成带有 API 的 `type`、`message`、`param` 以及 `kaeso-request-id` 的 `ApiError`（`src/api/errors.ts`）。
- **列表**使用游标分页（`src/api/paging.ts`），**导出**是流式下载（`src/api/download.ts`）。
- **搜索参数**：每个路由在同一个函数中校验自己的搜索参数，由 `validateSearch` 和页面的 `Route.useSearch({ select })` 共用。页面不认识的值会回退到默认值。
- **数据新鲜度**（`src/query.ts`）：缓存的数据会立即显示，并在后台重新获取。查询在 10 秒内视为新鲜，少数很少变化的查询保持更久，例如请求详情保持五分钟。会话在五秒内视为新鲜，因此同一页面的各部分共用它，并在窗口获得焦点时和每分钟重新检查。长列表只在仅加载了一页时才在获得焦点时刷新，因此回到窗口时不会重新加载已滚动浏览过的每一页。修改只重新加载它涉及的数据：组织本身的键是 `["orgs", org, "view"]`，因此重新加载组织不会影响组织内的列表。修改操作和客户端错误从不重试，其他失败的读取重试两次。

## 样式

控制台没有自己的样式。`@logicplanes/kaeso-ui` 提供每个可见元素和样式表，控制台代码只把 Tailwind 用于布局，并使用同一套令牌刻度。一个 Vite 插件把库中在首次绘制前运行的主题脚本作为 `/theme-init.js` 提供，因此内容安全策略不允许任何内联脚本。该策略还要求脚本使用 Trusted Types，因此任何代码都无法把字符串变成 HTML 或脚本；端到端测试的开发服务器也会发送这条规则。

## 打包

路由器会拆分路由（`autoCodeSplitting`），所以页面自己的代码随页面一起加载。构建会把来自 `@logicplanes/kaeso-ui` 的导入改写为库中各组件的入口，并把每个 `icons.name` 改写为该图标自己的导入（`vite.config.ts` 中的 `uiEntryImports`）。这样页面只携带它实际绘制的组件和图标。

首次绘制不需要的部分在使用时才加载：提示消息容器、命令面板、重新登录对话框、快捷键列表、“创建组织”、侧边栏菜单、提示框以及日期选择器的日历。侧边栏菜单和日历还会在页面空闲时预先加载，所以第一次点击就能立即打开。项目概览和组织概览的细分表、费用占比和时间段选择器，以及登录流程中输入邮箱地址之后的步骤，会与它们等待的数据一起加载。请求日志、项目审计日志和项目概览在路由的 loader 中开始加载数据，所用的模块（`src/api/queries/route-prefetch.ts`）只由这些路由加载。

当某个路由首次绘制所需的代码超出 `scripts/budget.mjs` 中的上限，或 `src/features` 中的页面代码进入入口时，`pnpm build` 会失败。要回到上限以内：

- 路由文件只从其页面导入类型。路由树位于入口中，导入值会把该页面带进每个页面。
- 入口导入、但只有后续页面才用到的代码，单独放进一个模块。
- 首次绘制用不到的部分在使用时或页面空闲时再加载。

## 错误

每个错误都是一条提示消息；页面中从不显示错误。

- 修改操作通过 `useApiMutation`（`src/auth/mutation.ts`），公开表单通过 `useSubmit`，加载失败则由查询缓存的处理函数（`src/query.ts`）处理，它会提供“重试”。
- 网关返回的失败带有请求 ID。
- 对目录模型和限额的编辑会发送 `If-Match`，带上编辑所基于的修订号。收到 `412` 时会重新加载已变化的内容，提示这一点，并关闭编辑对话框。
- 对象不存在（404）是页面或侧滑面板自己的状态；会话结束则跳转到登录页。
