Kaeso 内置了以下服务商，按名称排列。如何使用服务商以及它们之间的差异，见[服务商](providers.md)。每个服务商提供哪些 API，见[各服务商的 API](provider-apis.md)。组织还可以添加使用其中某种格式的自有服务器（[自定义服务商](../console/custom-providers.md)）。

## 各列说明

- **服务商。** 控制台显示的名称，后跟 ID。ID 用于在模型名称（如 `groq/llama-3.3-70b-versatile`）和[设置](../self-hosting/configuration.md#服务商设置)中指定服务商。
- **格式。** Kaeso 调用该服务商所用的 API 格式。服务商无法为其计数的模型，由 Kaeso 估算计数，音频、视频和决策模型除外（[服务商之间的差异](providers.md#服务商之间的差异)）。模型使用第一种格式，除非其**发送格式**指定了另一种（[模型的参数](../console/models-and-aliases.md#更改模型的参数)）。未指定时，Anthropic 应用的请求按原样发往 DeepSeek、Moonshot（K3 模型）、QwenCloud（Qwen 模型）、Baidu Qianfan、DeepInfra、OpenRouter、Hugging Face、Ollama Cloud、Tencent TokenHub、Fireworks AI、SambaNova 和 Vercel 的 Messages API（[原生 Messages API](../development/kpp/anthropic-messages-providers.md#原生-messages-api)）。**Embeddings** 和 **Gemini Embeddings** 表示该服务商提供嵌入模型，可用于 `/v1/embeddings`。**Cohere Rerank**、**Jina Rerank** 和 **Voyage Rerank** 表示它提供重排序模型，可用于 `/v1/rerank`。**Token 计数**表示它可以为 `/v1/messages/count_tokens` 和 `/v1/responses/input_tokens` 计算 Token 数。决策通过每个服务商自己的决策 API 发送，[各服务商的 API](provider-apis.md) 列出了它们。
- **主机。** 服务商默认基础 URL 的主机，实例必须能够访问它。如果您[设置了基础 URL](../self-hosting/configuration.md#服务商设置)，则以该地址为准。
- **密钥。** 在哪里创建密钥，以及密钥的开头（[服务商密钥](../console/provider-keys.md)）。

## 补充说明

关于部分服务商的其他须知事项。通过基础 URL 指向其他地域的服务商仍沿用其默认地域的模型和价格（[服务商设置](../self-hosting/configuration.md#服务商设置)）。服务商会改名或拒绝的每个 Chat Completions 字段，见[服务商配置](../development/kpp/openai-chat-providers.md#服务商配置)：

- **Amazon Bedrock。** 你自己 AWS 账户中的模型，例如 `us.anthropic.claude-sonnet-5`、`deepseek.v3.2` 和 `global.openai.gpt-6-sol`。服务商密钥可以是 Bedrock API 密钥、AWS 访问密钥，或在运营方允许时使用网关自身的 AWS 身份（见 [Amazon Bedrock 密钥](../console/provider-keys.md#amazon-bedrock-密钥)）：长期 Bedrock API 密钥以 `ABSK` 开头；短期密钥以 `bedrock-api-key-` 开头，最多有效 12 小时，且只能在生成它的区域使用。使用 AWS 凭证时，Kaeso 以 Signature Version 4 在密钥的区域为请求签名，在你自己的基础 URL 后面也是如此。每个密钥调用你为它选择的区域，即该区域的运行时端点 `bedrock-runtime.<region>.amazonaws.com`；[你设置的基础 URL](../self-hosting/configuration.md#服务商设置)（例如 VPC 端点）会替换所有区域的主机。Kaeso 按 AWS [API 兼容性](https://docs.aws.amazon.com/bedrock/latest/userguide/models-api-compatibility.html)表为每个模型列出的格式发送请求，目录中注明了该格式：Claude 模型以 Messages 发送到 `/anthropic/v1/messages`，Bedrock API 密钥作为 `x-api-key`；其他模型以 Chat Completions 发送到 `/openai/v1/chat/completions`；两者都不支持的聊天模型（例如 Amazon Nova、Meta Llama、Writer Palmyra 以及 Claude Sonnet 4.6 及更早版本）通过 Bedrock 自有的 Converse API 发送到 `/model/{modelId}/converse`（见 [Amazon Bedrock Converse](../development/kpp/bedrock-converse.md)）。推理配置文件 ID（例如 `us.…`、`eu.…` 和 `global.…`）按原样调用；密钥能调用哪些配置文件取决于其区域。闭源权重 GPT 模型的基础模型 ID 会在发送前被拒绝，因为 bedrock-runtime 只接受这些模型的推理配置文件 ID。Kaeso 估算 Token 计数（bedrock-runtime 只以自有格式计数），也拒绝 `mcp_servers` 和 `container`（Bedrock 上的 Claude 不支持）。bedrock-runtime 不列出模型，因此**检查可用性**会把每个模型标为无法确定；第一个请求会报告被拒绝的密钥。
- **AssemblyAI。** AssemblyAI 的 Sync API，`universal-3-6-pro`，以 AssemblyAI 自己的格式调用：每份转写上传一次，在同一请求中返回。它只提供 [Audio API](../api/audio.md) 的转写，不提供语音合成。Sync API 接受最长 20 分钟、最大 256 MB 的音频，并在 30 秒内返回，否则返回超时错误。它不检测语言，只能引导到 32 种语言（为其中一种发送 `language`，或省略它），不标注说话人，因此 `diarized_json` 会被拒绝，并且只提供词级时间，Kaeso 据此生成 `verbose_json`、`srt` 和 `vtt`。如需在欧盟处理，请将 AssemblyAI 的[基础 URL](../self-hosting/configuration.md#服务商设置)设为 `https://sync.eu.assemblyai.com`，使用同样的密钥。**检查可用性**无法检查 AssemblyAI 的密钥，因为 Sync API 没有不经转写就能检查密钥的请求；第一次转写会显示密钥是否有效（[AssemblyAI](../development/kpp/assemblyai.md)）。
- **Azure。** 即 Azure OpenAI 和 Microsoft Foundry：Azure 资源部署的模型，例如 `gpt-5`、`gpt-5-mini` 以及 DeepSeek、Grok、Llama 和 Mistral 的模型，还有嵌入模型（例如 `text-embedding-3-small`），通过 Azure 的 OpenAI v1 API（`{endpoint}/openai/v1`）调用。密钥是某个资源的 KEY 1 或 KEY 2，并注明该资源的端点，例如 `https://example.openai.azure.com`，资源的 **Keys and Endpoint** 页面会在密钥旁显示它（[服务商密钥](../console/provider-keys.md#azure-密钥)）；Kaeso 以 `api-key` 发送密钥。密钥也可以是 Microsoft Entra ID 服务主体，适用于关闭了密钥访问的资源：Kaeso 用其客户端密码换取访问令牌，并作为 Bearer 发送。请求指定的是部署，而不是模型：部署名称与模型 ID 不同时，请把该模型的**服务商模型 ID** 设为部署名称（[更改模型的参数](../console/models-and-aliases.md#更改模型的参数)）。Kaeso 调用 Chat Completions；对于支持 Responses 的部署，可在模型的**发送格式**中选择 Responses。Chat 应用会按 Azure 发送的原样收到其内容筛选结果；被筛选器拦截的提示会以内容筛选错误到达任何应用，被它截停的回复以 `content_filter` 结束。Azure 列出的是资源可以部署的模型，而不是它的部署，因此**检查可用性**只确认密钥及其端点可用，并把每个模型标为无法确定。KPMR 中的价格是 Azure 的 Global Standard 价格；Data Zone 和区域部署更贵，按 Azure 价格表约贵 10% 和 21%，请在这些模型的参数中设置价格。Claude 部署只响应 `/anthropic` 下的 Anthropic Messages API，图像、语音合成和转写在 v1 API 中仅为预览版，因此暂时都无法调用。
- **Baidu Qianfan。** 即百度智能云在中国大陆的模型平台百度千帆，提供百度的文心（ERNIE）模型（例如 `ernie-5.1` 和 `ernie-5.5-flash-preview`）、其他厂商的模型（例如 `deepseek-v4-pro`、`glm-5.3` 和 `qwen3.5-397b-a17b`），以及嵌入模型 `embedding-v1`、`tao-8k`、`bge-large-*` 和 `qwen3-embedding-*`，它们以固定尺寸提供 `/v1/embeddings`，因此 Kaeso 拒绝 `dimensions`。千帆的 API 位于 `/v2`，因此基础 URL `https://qianfan.baidubce.com/v2` 止于此处，Kaeso 在路径中省略 `/v1`。目录列出中国站的模型，其人民币价格换算为美元；国际站有自己的账号、模型 ID 和价格，如需使用，请将千帆的[基础 URL](../self-hosting/configuration.md#服务商设置)设为 `https://api.baiduqianfan.ai/v1`，并将其模型添加为自定义模型。`developer` 消息以 `system` 消息发送，最终用户 ID 以 `user` 发送。应用开启或关闭思考时，以 `thinking: {"type": …}` 发送给模型，模型的思考内容以 `reasoning_content` 读取，并以各种格式传给应用。千帆没有说明是否拒绝它不认识的字段，因此 Kaeso 拒绝其参考文档未列出的字段（例如 `logprobs`、`store` 和 `web_search_options`），并估算千帆不提供的 Token 计数。千帆自有的 `web_search` 可由 Chat 应用按原样发送。绑定了自定义应用的密钥可能需要千帆的 `appid` 请求头，Kaeso 不发送它；请在密钥上勾选默认应用。**检查可用性**读取千帆的模型列表，该列表需要密钥；列表未列出的模型（例如已部署的服务）判为无法确定，而不是不可用。DeepSeek 和 ERNIE 5.5 Flash 的价格是千帆的高峰时段价格；空闲时段为半价。
- **Baseten。** 即 Baseten Model APIs，Baseten 托管模型的共享端点，例如 `zai-org/GLM-5.3`、`moonshotai/Kimi-K3` 和 `deepseek-ai/DeepSeek-V4.1-Flash-1017`；专用部署有自己的地址，属于[自定义服务商](../console/custom-providers.md)。模型 ID 以模型的制作方开头，有些还以其他服务商的 ID 开头，例如 `openai/gpt-oss-120b`，因此请以 `baseten/openai/gpt-oss-120b` 的形式调用（[请求如何指定模型](../console/models-and-aliases.md#请求如何指定模型)）。每个应用的输出上限都会作为 `max_tokens` 发送给它，`developer` 消息会作为 `system` 消息发送，终端用户的 ID 会作为 `user` 发送。模型的思考内容来自 `reasoning_content`，可到达任何格式的应用，并在之后的轮次中以同一字段发回给 Baseten，这是 Beam 的要求；GLM 5.2 和 Nemotron 3 Ultra 只有在提供 `chat_template_args` 时才会思考，而只有 Chat 应用能发送它。Kaeso 只调用 Chat Completions：Baseten 的 Messages 端点不接受思考内容和图像，Model APIs 也不提供嵌入、图像或音频。
- **Cartesia。** Cartesia 的 Sonic 声音和 Ink Whisper 转写，以 Cartesia 自己的格式调用，密钥放在 `X-API-Key` 中，API 版本 `2026-08-14` 放在 `Cartesia-Version` 中。Cartesia 不生成文本，因此它提供 [Audio API](../api/audio.md)，不提供聊天。声音按 Cartesia 的 ID 指定；`alloy` 这样的名称会发给 Cartesia，由它回复没有该声音。语音以 mp3、wav 或 pcm 返回；`opus`、`aac` 和 `flac` 会被拒绝。Cartesia 的批量转写不检测语言，因此 Kaeso 拒绝没有 `language` 的转写。**检查可用性**读取一个声音，只能说明密钥有效：Cartesia 不列出模型。价格为 Pro 套餐每个积分的超额价格；更大的套餐更便宜（[Cartesia](../development/kpp/cartesia.md)）。
- **Cerebras。** 即 Cerebras Inference，提供 `gpt-oss-120b`、`qwen-3.8-27b` 等模型。`developer` 消息会作为 `system` 消息发送给它，终端用户的 ID 以 `user` 发送，Claude Code 或 Codex 在第一轮之后发送的系统消息的文本并入下一个用户轮次，没有参数的函数带上空的参数 schema。Grok CLI 发回的 `reasoning_content` 以 `reasoning` 到达它。它拒绝以 assistant 消息结尾的对话，因为 Cerebras 会重新回答，也拒绝 assistant 消息上的 `refusal`。Cerebras 对任何它不认识的字段（例如 `store`）返回 400，并且只接受 data URI 形式的图像。模型的思考内容可到达任何格式的应用；`gpt-oss-120b` 在 `reasoning_effort` 为 `low`、`medium` 或 `high` 时思考，`qwen-3.8-27b` 还接受 `none`，其他强度由 Kaeso 拒绝。

- **DeepSeek。** `developer` 消息会作为 `system` 消息发送给它。Kaeso 拒绝 Anthropic 应用的 `container` 和 `mcp_servers`，DeepSeek 会忽略。

- **Fireworks AI。** 即 Fireworks AI 的无服务器开放模型，例如 `accounts/fireworks/models/glm-5p3-flash` 和 `accounts/fireworks/models/kimi-k3`，以完整的资源名称调用（`fireworks-ai/accounts/fireworks/models/kimi-k3`），地址为 `https://api.fireworks.ai/inference`。Kaeso 默认调用 Chat Completions；模型的**发送格式**可以选择 Messages，即 Fireworks 兼容 Anthropic 的端点。终端用户的 ID 以 `user` 发送给它，视频以 `video_url` 部分发送给支持视频的模型。模型的思考内容来自 `reasoning_content`，可到达任何格式的应用，并以同一字段发回 Fireworks。当 `max_tokens` 超出上下文窗口所剩的空间时，Fireworks 会将其调低而不是拒绝，除非 Chat 应用发送 `context_length_exceeded_behavior: "error"`。它的嵌入模型 `qwen3-embedding-8b`，以及使用 Hugging Face ID 的较旧模型（例如 `nomic-ai/nomic-embed-text-v1.5`）提供 `/v1/embeddings`。如需只在美国处理，请将 Fireworks 的[基础 URL](../self-hosting/configuration.md#服务商设置) 设为 `https://us.api.fireworks.ai/inference`。
- **Gemini Enterprise Agent Platform。** Google Cloud 面向 Gemini 模型的平台，提供 `gemini-3.5-flash`、`gemini-3.1-pro-preview` 等模型。Kaeso 像调用 Google AI Studio 一样以 Gemini 自己的格式调用它，并按平台 Token 计数参考的要求在每个 content 上写入 `role`。服务商密钥可以是快速模式 API 密钥，以 `x-goog-api-key` 发送到 `aiplatform.googleapis.com`，只能调用快速模式列出的 Gemini 模型；也可以是服务账号的 JSON 密钥，Kaeso 用它自行向 Google 获取访问令牌，并在你选择的位置调用该密钥所属的项目（[添加 Google Cloud 服务账号密钥](../console/provider-keys.md#添加-google-cloud-服务账号密钥)）。每个位置有自己的主机：`global` 为 `aiplatform.googleapis.com`，多区域 `us` 和 `eu` 为 `aiplatform.us.rep.googleapis.com` 和 `aiplatform.eu.rep.googleapis.com`，`us-east5` 等区域为 `<location>-aiplatform.googleapis.com`。[你设置的基础 URL](../self-hosting/configuration.md#服务商设置)（例如 Private Service Connect 端点）会替换所有位置的主机。Kaeso 按模型所属的系列选择格式：Gemini 模型使用 Gemini 自己的格式；Claude 模型（`claude-*`，例如 `claude-opus-5-5@default`）通过平台的 `rawPredict` 使用 Messages 格式；ID 中写明发布方的合作伙伴模型和开放模型（`meta/llama-4-maverick-17b-128e-instruct-maas`）通过平台的 OpenAI 兼容端点以 Chat Completions 发送。自定义模型遵循同一规则，其**发送格式**可以选择其他格式。Claude 和合作伙伴模型需要服务账号密钥；使用快速模式密钥时，Kaeso 会在发送前拒绝它们。平台只以 Mistral 自己的格式提供 Mistral 模型，Kaeso 会拒绝它们，平台的嵌入模型也会被拒绝。OpenAI 兼容端点会接受某些字段却不加处理，例如 `logit_bias`、`logprobs` 和 `store`，Kaeso 会拒绝这些字段。Token 计数适用于 Gemini 和 Claude 模型。**检查可用性**会计算一个单词提示的 Token 数，Google 对此不收费，因此能识别错误的密钥，以及密钥的项目或位置不提供的 Gemini 或 Claude 模型；对合作伙伴模型则无法判断。服务账号密钥还需要访问 `oauth2.googleapis.com`。

- **Mistral。** `developer` 消息会作为 `system` 消息发送给它，部分字段以它自己的名称发送，例如 `seed` 改为 `random_seed`；它拒绝其他一些字段（例如 `logit_bias`），也拒绝以助手消息结尾的对话。

- **Ollama Cloud。** 由 Ollama 在自己的服务器上运行的模型，例如 `gpt-oss:120b`。模型 ID 保留 Ollama 在冒号后的标签。每个应用的输出上限都以 `max_tokens` 发送给它，因为 Ollama 会忽略 `max_completion_tokens`；它拒绝 `logprobs`、`top_logprobs` 和 `logit_bias`，因为 Ollama 接受这些字段却不作处理。模型的推理内容会以各种格式送达应用。Ollama 的 Messages API 只接受 `auto` 的 `tool_choice`，Kaeso 拒绝 Anthropic 应用的其他值。Ollama 的免费套餐只包含部分模型：对其他模型，Ollama 返回 402，应用会将其作为被拒绝的服务商密钥收到。Ollama 列出模型时不检查密钥，因此**检查可用性**无法发现错误的密钥；使用该密钥的第一个请求会报告密钥被拒绝。本地 Ollama 服务器不需要密钥；请将其添加为服务器为 Ollama 的[自定义服务商](../console/custom-providers.md#服务器软件)。

- **Standard Compute。** 面向前沿模型和开放模型、带每月计算预算的包月套餐。它的路由器 `standardcompute`，即 **Smart routing**，会为每个请求从 Standard Compute 控制台中启用的模型里选择一个，添加 Standard Compute 的模型时排在最前面。它的回复把模型称为 `StandardCompute`；只有 Standard Compute 的请求日志会显示由哪个模型作答。确切的 ID（例如 `anthropic/claude-sonnet-5.5`）会固定使用一个模型，`:eu` 和 `:us` 变体（例如 `openai/gpt-5.6-luna:eu`）只在欧洲或美国的提供商端点上运行。Standard Compute 按套餐计费而不是按 Token 计费，因此它的模型没有价格：请求的费用显示为**未知**，除非管理员手动为这些模型设置价格，否则支出预算会拒绝这些模型（见[支出预算无法计价的功能](../console/limits-and-budgets.md#支出预算无法计价的功能)）。每月预算用完时，应用会收到因计费原因被拒绝的服务商密钥；Standard Compute 的速率限制会以速率限制的形式到达应用，并带有其 `retry-after`。模型的思考会以每种格式到达应用，来自 `reasoning`。Kaeso 只调用 Chat Completions：Standard Compute 的 Messages 端点会忽略思考，它也不提供嵌入、图片或音频。Kaeso 会估算 Token 计数（Standard Compute 只根据请求大小估算），并拒绝视频（其模型的提供商不接受以链接形式发送的视频）。Standard Compute 列出模型时不检查密钥，因此**检查可用性**无法发现错误的密钥，并且会把密钥列表中缺少的模型判定为无法确定，而不是不可用。如需使用欧盟或美国端点，请将 Standard Compute 的[基础 URL](../self-hosting/configuration.md#服务商设置)设为 `https://eu.stdcmpt.com` 或 `https://us.stdcmpt.com`。
- **StepFun。** 即 StepFun 的国际 API，提供 `step-5-preview`、`step-3.7-flash` 和 `step-3.5-flash` 等 Step 模型。如需使用 KPMR 列为 `stepfun` 的中国服务，请将 StepFun 的[基础 URL](../self-hosting/configuration.md#服务商设置) 设为 `https://api.stepfun.com`，并使用那里的密钥；一个安装只能访问其中一个，目录保留国际服务以美元计的价格。每个应用的输出上限都会作为 `max_tokens` 发送给它，`developer` 消息会作为 `system` 消息发送，视频以 `video_url` 部分发送给支持视频的模型，并省略终端用户的 ID 和 Responses 应用的提示缓存键，因为 StepFun 的 API 不接受；StepFun 会自行缓存提示。模型的思考内容来自 `reasoning` 或 `reasoning_content`，可到达任何格式的应用。StepFun 的推理模型总会思考：`reasoning_effort` 接受 `low`、`medium` 或 `high`，`step-3.5-flash` 和 `step-3.5-flash-2603` 只接受 `low` 或 `high`，其他强度由 Kaeso 拒绝。Kaeso 会拒绝 StepFun 的 API 参考中没有的字段，例如 `presence_penalty`、`seed`、`logprobs` 和 `store`，也会估算 Token 计数，StepFun 只以自己的格式提供它。它的语音合成和转写模型暂时还不能通过 Kaeso 使用。
- **Tencent TokenHub。** 即腾讯云的大模型服务平台，提供腾讯的 Hy 模型（例如 `hy4`、`hy3` 和翻译模型 `hy-mt2-*`）、其他厂商的模型（例如 `deepseek-v4-pro`、`glm-5.3`、`kimi-k3` 和 `minimax-m3`），以及通过 `/v1/embeddings` 以固定维度提供的嵌入模型 `kinfra-text-embedding-0.6b` 和 `kinfra-text-embedding-4b`，因此 Kaeso 拒绝 `dimensions`。Kaeso 调用广州地域，该地域在中国大陆处理请求。如需使用其他地域，请设置 TokenHub 的[基础 URL](../self-hosting/configuration.md#服务商设置)，并使用为该地域创建的密钥：新加坡为 `https://tokenhub-intl.tencentmaas.com`；腾讯云国际站账户为 `https://tokenhub-intl.tencentcloudmaas.com`（新加坡）、`https://tokenhub.tencentcloudmaas.com`（广州）或 `https://tokenhub-us.tencentcloudmaas.com`（硅谷）。密钥只能在其所属的地域和站点使用，一个安装只能访问其中一个。模型须先在 TokenHub 控制台开通，密钥才能调用。有些 ID 以其他服务商的 ID 开头，例如 `deepseek/deepseek-v4-pro`，因此请以 `tencent-tokenhub/deepseek/deepseek-v4-pro` 的形式调用（[请求如何指定模型](../console/models-and-aliases.md#请求如何指定模型)）。`developer` 消息会作为 `system` 消息发送，视频会以 `video_url` 部分发送给支持视频的模型。模型的思考内容来自 `reasoning_content`，可到达任何格式的应用。Hy4 支持 `reasoning_effort` `high`，Hy3 支持 `low` 或 `high`；TokenHub 用自己的级别 `no_think` 关闭它们的思考，Kaeso 不发送该级别，因此关闭思考的应用会得到它们的最低级别，与[始终推理的模型](../development/kpp/reasoning.md#始终推理的模型)相同。TokenHub 会静默忽略它不认识的字段，因此 Kaeso 拒绝其参考文档未列出的字段，例如 `logit_bias`、`store` 和 `service_tier`，并估算 Token 计数，因为 TokenHub 不提供。DeepSeek 模型在北京时间工作日的工作时段价格翻倍；目录列出的是该高峰价格。TokenHub 的多模态嵌入、图像、视频和语音使用它自己的格式，不会被使用。
- **TypeSafe。** TypeSafe 的 System One 模型 Jev 1.14（`jev-1.14.0`）和 Jev 1.13（`jev-1.13.0`），以及别名 `jev-latest` 和 `jev-preview`。它们回答决策问题、不生成文本，因此以每种决策格式提供 [Decisions API](../api/decisions.md)，不提供聊天。Kaeso 把每个请求发送到 TypeSafe 的 `/v1/systemone`，图片作为 `assets` 发送，应用上传的图片仍作为分段发送。带图片或边界框问题的请求会附带 `TypeSafe-Danger-Zone-Images: true`。当 Kaeso 估计 state 加全部问题超过 64k token，或 state 加任一问题超过 32k 时，还会发送 `TypeSafe-Danger-Zone-Long-Context: true`。它按每 token 4 字节文本估算、不计图片，并在 `kaeso-adapted` 中把该标头记为 `long_context`。长上下文价格不变，但没有它时 TypeSafe 会拒绝更长的请求。边界框问题需要 Jev 1.14，输出 token 免费。TypeSafe 不认识的密钥（401）和不带密钥的请求（403）都会以服务商密钥被拒绝的形式返回给应用。**检查可用性**会读取 TypeSafe 的模型列表，该列表以自己的格式列出模型和别名；列表中没有的模型结果为无法确定，而不是不可用。
- **Upstage。** Upstage 的 Solar 模型 `solar-pro4` 和 `solar-mini4`，它们是带日期快照（例如 `solar-pro4-260806`）的别名，回复中会写出快照名；以及它的嵌入模型 `solar-embedding-2-query` 和 `solar-embedding-2-passage`，提供 `/v1/embeddings`：请用 `-query` 模型嵌入问题，用 `-passage` 模型嵌入被检索的文档；它们的向量为 1,024 维，因此 Kaeso 拒绝 `dimensions`。每个应用的输出上限都以 `max_tokens` 发送给它，`developer` 消息会作为 `system` 消息发送，并省略终端用户的 ID，因为 Upstage 的 API 不接受。Solar 模型只在应用要求时思考：`low` 到 `max` 的推理强度会开启思考，思考内容来自 `reasoning`，可到达任何格式的应用。Kaeso 拒绝 Upstage 的 API 参考未列出的字段，例如 `stop`（Anthropic 应用的 `stop_sequences`）、`seed` 和 `logit_bias`，并估算 Token 计数，因为 Upstage 只提供公开的分词器来计数。Upstage 的模型列表需要有效密钥且没有文档，因此**检查可用性**会将列表中没有的模型视为无法确定，而不是不可用。如需使用处于封闭测试阶段的韩国区域，请将 Upstage 的[基础 URL](../self-hosting/configuration.md#服务商设置)设为 `https://kr.api.upstage.ai`；该区域只提供 `solar-mini4`。
- **Venice。** Venice 的私有模型（例如 `zai-org-glm-5-1` 和 `venice-uncensored-1-2`）、它转发且不透露请求者身份的其他厂商模型（例如 `claude-opus-5-5`），以及它的嵌入模型（例如 `text-embedding-bge-m3`），提供 `/v1/embeddings`，基础 URL 为 `https://api.venice.ai/api`。除非明确关闭，Venice 会在每个请求前加上自己的系统提示词，因此除非 Chat Completions 应用自己设置了该键，Kaeso 会在 `venice_parameters` 中加上 `include_venice_system_prompt: false`；应用的其他 `venice_parameters` 按原样到达 Venice。省略终端用户的 ID，因为 Venice 会丢弃它。模型的思考内容来自 `reasoning_content`，可到达任何格式的应用。Venice 会以自己的错误拒绝它不认识的字段；Kaeso 拒绝 `store` 和 `metadata`（Venice 接受但不处理），并估算 Token 计数，因为 Venice 不提供。Venice 的模型列表只列出文本模型，因此**检查可用性**会将嵌入模型视为无法确定，而不是不可用。KPMR 未收录 `e2ee-*` 模型，它们需要在应用中加密。
- **Vercel。** 即 Vercel AI Gateway，另一个网关，其自身的路由和回退在 Kaeso 之后运行。模型 ID 包含模型开发者，例如 `openai/gpt-5-nano`。请以 `vercel/openai/gpt-5-nano` 的形式调用，这样请求不会发往该开发者自己的服务商（[请求如何指定模型](../console/models-and-aliases.md#请求如何指定模型)）。模型的**发送格式**可以选择 Vercel 同样提供的 Responses 或 Messages；通过 Messages，Vercel 会把 Anthropic 的 `cache_control` 传给 Claude 模型。Kaeso 按目录中的价格记录费用，而不是按 Vercel 在 `usage.cost` 中报告的费用，后者不含 Vercel 自己的附加费。Vercel 只为 Claude 模型精确计数 Token，对其余模型只做估算，因此 Kaeso 对所有 Vercel 模型都估算 Token 数。Vercel 回答模型信息时不检查密钥，因此**检查可用性**无法发现错误的密钥；使用该密钥的第一个请求会报告密钥被拒绝。免费套餐的 Vercel 账户无法调用 Claude 等付费模型：Vercel 返回 403，应用会将其视为服务商密钥被拒绝，请求日志中保留 Vercel 给出的原因。
- **Volcengine Ark。** 即字节跳动在中国大陆的模型平台火山方舟，提供 `doubao-seed-2-1-pro-260915` 等豆包 Seed 模型，以及 `deepseek-v4-1-flash-261017`、`kimi-k3-1-pro-261024` 等其他厂商的模型。一个密钥属于一个项目，只能访问该项目的模型，且每个模型都须先在方舟控制台开通。请求也可以指定账户创建的推理接入点（`ep-…`），这是访问精调模型或预留模型的唯一方式：请将其添加为以 Chat Completions 发送的[自定义模型](../console/models-and-aliases.md)，并填写价格。如需使用字节跳动的国际服务 BytePlus ModelArk（有自己的密钥和模型 ID），请将 Volcengine Ark 的[基础 URL](../self-hosting/configuration.md#服务商设置) 设为 `https://ark.ap-southeast.bytepluses.com/api/v3`，并使用那里的密钥；它的模型不在 KPMR 中，请将其添加为自定义模型。方舟的 API 位于 `/api/v3`，因此基础 URL 以此结尾，Kaeso 的路径中省略 `/v1`。应用关闭思考时会以 `thinking: {"type": "disabled"}` 发送给模型，强度以 `reasoning_effort` 发送；模型的思考内容来自 `reasoning_content`，可到达任何格式的应用，较新的 Seed 模型随之发送的加密原文会在下一轮发回。Kaeso 的输出上限以 `max_completion_tokens` 发送，它同时计入思考和回答，最大 65536；Chat 应用自己的 `max_tokens` 只限制回答。Kaeso 省略终端用户的 ID，因为方舟的 API 不接受，并拒绝它不支持的字段，例如 `seed` 和 `n`、OpenAI 的 `service_tier` 值 `priority` 和 `scale`，以及不生效的 `web_search_options` 键。它的嵌入模型只提供多模态端点、整段输入只返回一个向量，因此不被使用；Token 计数也不被使用。
- **Voyage AI。** Voyage AI 的文本嵌入模型（例如 `voyage-4`、`voyage-4-lite` 和 `voyage-code-4`），提供 `/v1/embeddings`；以及它的重排序模型（例如 `rerank-3` 和 `rerank-3-lite`），提供 `/v1/rerank`（[重排序 API](../api/rerank.md)）。MongoDB 将 Voyage AI 的 API 作为 Atlas 的 Embedding and Reranking API 出售：在 Atlas 的 **AI Model APIs** 下创建模型 API 密钥，Kaeso 调用 `https://ai.mongodb.com`。Voyage AI 自己控制台中的密钥（`pa-…`）适用于 `https://api.voyageai.com`，限定区域的密钥适用于 `https://eu.ai.mongodb.com` 或 `https://us.ai.mongodb.com`，其计费比目录价格高 10%；密钥只在自己的主机上有效，因此请相应设置 Voyage AI 的[基础 URL](../self-hosting/configuration.md#服务商设置)，一个安装只能访问其中之一。`dimensions` 以 `output_dimension` 发送，只接受 256、512、1024 或 2048；浮点数以不带 `encoding_format` 的方式发送，这是 Voyage AI 的默认值；Voyage AI 自有的 `input_type`、`truncation` 和 `output_dtype` 按原样发送。Voyage AI 会拒绝它不认识的字段，因此 Kaeso 在发送前拒绝最终用户 ID、其他尺寸以及作为输入的 token ID。重排序请求的 `top_n` 以 `top_k` 发送；Kaeso 拒绝 `max_tokens_per_doc`、Cohere 自有的字段以及除 `text` 外还有其他字段的文档。Voyage AI 不提供模型列表，也不在没有密钥的情况下查询模型，因此**检查可用性**会将每个模型判为无法确定，且无法发现错误的密钥；使用该密钥的第一个请求会报告密钥被拒绝。它的多模态嵌入和上下文嵌入使用各自的端点，不会被使用。
- **Z.ai。** 即 Z.ai 的 Anthropic 兼容 API，提供 `glm-5.3`、`glm-4.6` 等 GLM 模型。Kaeso 以 Messages 格式调用它，密钥放在 `x-api-key` 中，因此各种格式的应用都能访问它，Anthropic 应用的请求按应用原样发送。Z.ai 没有说明它接受哪些 Anthropic 字段，因此 Kaeso 会全部发送，是否拒绝由 Z.ai 决定；重复的提示词由 Z.ai 自动缓存。Z.ai 发送自己的错误码：余额不足（`1113`）以被拒绝的服务商密钥送达应用，而不是速率限制；服务过载（`1305`）以过载送达；提示词过长（`1261`）也以提示词过长送达，这样 Claude Code 会压缩对话。**检查可用性**能发现错误的密钥；Z.ai 没有说明模型列表，因此能否发现 Z.ai 不提供的模型尚未验证。Z.ai 按密钥类型对每次调用计费，并且只允许在其列出的编程工具中使用 GLM Coding Plan 密钥，因此请使用标准 API 密钥。在中国大陆，请将 Z.ai 的[基础 URL](../self-hosting/configuration.md#服务商设置)设为 `https://open.bigmodel.cn/api/anthropic`，并使用 bigmodel.cn 的密钥。

## 商标

所有商标和标志均归其各自所有者所有。Kaeso 与这些服务商及其所提供模型的开发公司均无关联，也未获得其认可或赞助。控制台显示服务商的标志，仅用于标明密钥、模型或请求所属的服务商；在关于单个模型的行中，则显示开发该模型的公司的标志，这一信息从模型 ID 中读取，因此 Amazon Bedrock 上的 GPT 模型显示 OpenAI 的标志。Anthropic、Cerebras、Cohere、Google、Groq、Z.ai、MiniMax、Standard Compute、Cloudflare、TypeSafe、DeepInfra、Upstage、IONOS、Novita AI、Volcengine、OVHcloud、StepFun、Tencent、Microsoft 以及 QwenCloud 的所有者 Alibaba Cloud 在其条款中限制使用其标志，许多模型开发商也是如此；Kaeso 仅出于此目的显示它们的标志，保留所有者的形状和颜色，只在颜色需要在 Kaeso 的浅色和深色背景上保持可见时才做必要的调整。Mistral 的品牌页面要求不要给其图标重新着色或加框，PixVerse 要求不要更改其渐变；Kaeso 以它们自己的颜色显示这两个标志，放在与其他标志相同的中性底块上。AWS 的[商标指南](https://aws.amazon.com/trademark-guidelines/)只允许以纯文本形式使用其商标，fal 的[条款](https://fal.ai/legal/terms-of-service)禁止未经其书面许可使用其标志，百度的[条款](https://cloud.baidu.com/doc/Agreements/s/Pjwvy1utr)禁止未经其许可复制其标志，因此 Amazon Bedrock、fal 和百度千帆（Baidu Qianfan），以及亚马逊和百度自己的模型，都显示服务商图标而不是标志，与运行其他服务器软件或代理的自定义服务商相同。[NOTICE.md](https://github.com/logicplanes/kaeso/blob/dev/NOTICE.md#trademarks) 列出了每个标志的来源。
