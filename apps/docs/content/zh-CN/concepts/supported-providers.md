Kaeso 内置了以下服务商，按名称排列。如何使用服务商以及它们之间的差异，见[服务商](providers.md)。每个服务商提供哪些 API，见[各服务商的 API](provider-apis.md)。组织还可以添加使用其中某种格式的自有服务器（[自定义服务商](../console/custom-providers.md)）。

## 各列说明

- **服务商。** 控制台显示的名称，后跟 ID。ID 用于在模型名称（如 `groq/llama-3.3-70b-versatile`）和[设置](../self-hosting/configuration.md#服务商设置)中指定服务商。
- **格式。** Kaeso 调用该服务商所用的 API 格式。模型使用第一种格式，除非其**发送格式**指定了另一种（[模型的参数](../console/models-and-aliases.md#更改模型的参数)）。**Embeddings** 和 **Gemini Embeddings** 表示该服务商提供嵌入模型，可用于 `/v1/embeddings`。**Token 计数**表示它可以为 `/v1/messages/count_tokens` 和 `/v1/responses/input_tokens` 计算 Token 数。决策通过每个服务商自己的决策 API 发送，[各服务商的 API](provider-apis.md) 列出了它们。
- **主机。** 服务商默认基础 URL 的主机，实例必须能够访问它。如果您[设置了基础 URL](../self-hosting/configuration.md#服务商设置)，则以该地址为准。
- **密钥。** 在哪里创建密钥，以及密钥的开头（[服务商密钥](../console/provider-keys.md)）。

## 补充说明

关于部分服务商的其他须知事项。服务商会改名或拒绝的每个 Chat Completions 字段，见[服务商配置](../development/kpp/openai-chat-providers.md#服务商配置)：

- **Baseten。** 即 Baseten Model APIs，Baseten 托管模型的共享端点，例如 `zai-org/GLM-5.3`、`moonshotai/Kimi-K3` 和 `deepseek-ai/DeepSeek-V4.1-Flash-1017`；专用部署有自己的地址，属于[自定义服务商](../console/custom-providers.md)。模型 ID 以模型的制作方开头，有些还以其他服务商的 ID 开头，例如 `openai/gpt-oss-120b`，因此请以 `baseten/openai/gpt-oss-120b` 的形式调用（[请求如何指定模型](../console/models-and-aliases.md#请求如何指定模型)）。每个应用的输出上限都会作为 `max_tokens` 发送给它，`developer` 消息会作为 `system` 消息发送，终端用户的 ID 会作为 `user` 发送。模型的思考内容来自 `reasoning_content`，可到达任何格式的应用，并在之后的轮次中以同一字段发回给 Baseten，这是 Beam 的要求；GLM 5.2 和 Nemotron 3 Ultra 只有在提供 `chat_template_args` 时才会思考，而只有 Chat 应用能发送它。Kaeso 只调用 Chat Completions：Baseten 的 Messages 端点不接受思考内容和图像，Model APIs 也不提供嵌入、图像或音频。Kaeso 拒绝 Token 计数，因为 Baseten 不提供。
- **Cerebras。** 即 Cerebras Inference，提供 `gpt-oss-120b`、`qwen-3.8-27b` 等模型。`developer` 消息会作为 `system` 消息发送给它，终端用户的 ID 以 `user` 发送，Claude Code 或 Codex 在第一轮之后发送的系统消息的文本并入下一个用户轮次，没有参数的函数带上空的参数 schema。Grok CLI 发回的 `reasoning_content` 以 `reasoning` 到达它。它拒绝以 assistant 消息结尾的对话，因为 Cerebras 会重新回答，也拒绝 assistant 消息上的 `refusal`。Cerebras 对任何它不认识的字段（例如 `store`）返回 400，并且只接受 data URI 形式的图像。模型的思考内容可到达任何格式的应用；`gpt-oss-120b` 在 `reasoning_effort` 为 `low`、`medium` 或 `high` 时思考，`qwen-3.8-27b` 还接受 `none`，其他强度由 Kaeso 拒绝。
- **Cloudflare AI Gateway。** 即 Cloudflare 的 REST API，提供第三方模型（例如 `anthropic/claude-sonnet-5.5` 和 `openai/gpt-6-luna`，使用 Cloudflare 的 Unified Billing 额度或网关上存储的服务商密钥付费）以及 Workers AI 模型（例如 `@cf/zai-org/glm-4.7-flash`，通过 Workers AI 计费）。密钥是具有 **Workers AI Read** 权限的 Cloudflare API 令牌，并注明其调用的账户，以及可选的请求所经过的网关；未指定网关时，请求经过账户的 `default` 网关，Cloudflare 会在第一次请求时创建该网关（见[服务商密钥](../console/provider-keys.md#cloudflare-ai-gateway-密钥)）。Kaeso 按 Cloudflare 为每个模型列出的格式发送：Claude 模型以 Messages 发送，Cloudflare 只通过 Responses 提供的模型以 Responses 发送，其他所有模型以 Chat Completions 发送。网关的别名（`custom/…`）和动态路由（`dynamic/…`）以自定义模型的形式添加；动态路由只接受 Chat Completions。Kaeso 会拒绝 Token 计数，Cloudflare 不提供该功能。**检查可用性**会在 Cloudflare 的模型搜索中查找 Workers AI 模型；Cloudflare 是否提供其他模型只能通过它计费的请求得知，因此检查只确认密钥及其账户，并把该模型判定为无法确定。Workers AI 模型只接受 base64 数据形式的图片，不接受链接，部分模型只接受部分推理强度，目录中会列出。每个请求的日志会把 Cloudflare 的日志条目记为服务商请求。
- **Cohere。** 即 Cohere 的 [Compatibility API](https://docs.cohere.com/docs/compatibility-api)，它只覆盖 Cohere 自身 API 的一部分：无法通过它使用文档、引用和重排序。Cohere 拒绝部分字段，例如 `logit_bias` 和 `parallel_tool_calls: false`；单个 `stop` 字符串会以列表形式发送给它。它的推理模型只支持 `reasoning_effort` 为 `none` 或 `high`。它的 Embed 模型（例如 `embed-v4.0`）不在 KPMR 中：请将其添加为以 Embeddings 发送的自定义模型，并填写价格。
- **DeepSeek。** `developer` 消息会作为 `system` 消息发送给它。
- **Fireworks AI。** 即 Fireworks AI 的无服务器开放模型，例如 `accounts/fireworks/models/glm-5p3-flash` 和 `accounts/fireworks/models/kimi-k3`，以完整的资源名称调用（`fireworks-ai/accounts/fireworks/models/kimi-k3`），地址为 `https://api.fireworks.ai/inference`。Kaeso 默认调用 Chat Completions；模型的**发送格式**可以选择 Messages，即 Fireworks 兼容 Anthropic 的端点。终端用户的 ID 以 `user` 发送给它，视频以 `video_url` 部分发送给支持视频的模型。模型的思考内容来自 `reasoning_content`，可到达任何格式的应用，并以同一字段发回 Fireworks。当 `max_tokens` 超出上下文窗口所剩的空间时，Fireworks 会将其调低而不是拒绝，除非 Chat 应用发送 `context_length_exceeded_behavior: "error"`。它的嵌入模型 `qwen3-embedding-8b`，以及使用 Hugging Face ID 的较旧模型（例如 `nomic-ai/nomic-embed-text-v1.5`）提供 `/v1/embeddings`。Kaeso 拒绝Token 计数，因为 Fireworks 不提供。如需只在美国处理，请将 Fireworks 的[基础 URL](../self-hosting/configuration.md#服务商设置) 设为 `https://us.api.fireworks.ai/inference`。
- **Gemini Enterprise Agent Platform。** Google Cloud 面向 Gemini 模型的平台，提供 `gemini-3.5-flash`、`gemini-3.1-pro-preview` 等模型。Kaeso 像调用 Google AI Studio 一样以 Gemini 自己的格式调用它，并按平台 Token 计数参考的要求在每个 content 上写入 `role`。服务商密钥可以是快速模式 API 密钥，以 `x-goog-api-key` 发送到 `aiplatform.googleapis.com`，只能调用快速模式列出的 Gemini 模型；也可以是服务账号的 JSON 密钥，Kaeso 用它自行向 Google 获取访问令牌，并在你选择的位置调用该密钥所属的项目（[添加 Google Cloud 服务账号密钥](../console/provider-keys.md#添加-google-cloud-服务账号密钥)）。每个位置有自己的主机：`global` 为 `aiplatform.googleapis.com`，多区域 `us` 和 `eu` 为 `aiplatform.us.rep.googleapis.com` 和 `aiplatform.eu.rep.googleapis.com`，`us-east5` 等区域为 `<location>-aiplatform.googleapis.com`。[你设置的基础 URL](../self-hosting/configuration.md#服务商设置)（例如 Private Service Connect 端点）会替换所有位置的主机。Kaeso 按模型所属的系列选择格式：Gemini 模型使用 Gemini 自己的格式；Claude 模型（`claude-*`，例如 `claude-opus-5-5@default`）通过平台的 `rawPredict` 使用 Messages 格式；ID 中写明发布方的合作伙伴模型和开放模型（`meta/llama-4-maverick-17b-128e-instruct-maas`）通过平台的 OpenAI 兼容端点以 Chat Completions 发送。自定义模型遵循同一规则，其**发送格式**可以选择其他格式。Claude 和合作伙伴模型需要服务账号密钥；使用快速模式密钥时，Kaeso 会在发送前拒绝它们。平台只以 Mistral 自己的格式提供 Mistral 模型，Kaeso 会拒绝它们，平台的嵌入模型也会被拒绝。OpenAI 兼容端点会接受某些字段却不加处理，例如 `logit_bias`、`logprobs` 和 `store`，Kaeso 会拒绝这些字段。Token 计数适用于 Gemini 和 Claude 模型。**检查可用性**会计算一个单词提示的 Token 数，Google 对此不收费，因此能识别错误的密钥，以及密钥的项目或位置不提供的 Gemini 或 Claude 模型；对合作伙伴模型则无法判断。服务账号密钥还需要访问 `oauth2.googleapis.com`。
- **Google AI Studio。** 即 Google AI Studio 的 Gemini API，提供 `gemini-3.5-flash`、`gemini-3.1-pro-preview` 等 Gemini 模型、Gemma 模型，以及嵌入模型 `gemini-embedding-2` 和 `gemini-embedding-001`。Kaeso 以 Gemini 自己的格式调用它，密钥放在 `x-goog-api-key` 中，因此各种格式的应用都能访问它，Gemini 的思维签名在工具调用之间也得以保留。Gemini 3 模型按 KPMR 为其列出的推理强度级别思考，以 `thinkingLevel` 发送。Gemini 2.5 模型没有列出级别：Anthropic 应用的 `budget_tokens` 以 `thinkingBudget` 发送，其他应用的推理强度则被省略，并在 `kaeso-left-out` 中注明。托管网页搜索会被省略，因为 Gemini 的 `googleSearch` 不接受它的任何设置。AI Studio 的密钥以 `AIza` 或 `AQ.` 开头。免费层级的密钥每个模型每天只有很少的配额；超出后 Google 返回 429，应用会收到速率限制错误。**检查可用性**能识别错误的密钥。Google Cloud 面向 Gemini 模型的平台 Gemini Enterprise Agent Platform 是一个单独的服务商。
- **Groq。** `developer` 消息会作为 `system` 消息发送给它；它拒绝部分字段，例如 `logit_bias`。
- **Hugging Face。** 即 Hugging Face Inference Providers，一个路由器，会把每个请求转给提供该模型的服务商之一，例如 Groq、Cerebras 或 Novita，提供 `openai/gpt-oss-120b`、`deepseek-ai/DeepSeek-V4.1-Flash-1017` 和 `Qwen/Qwen3.8-27B` 等开放模型。服务商密钥是带有 **Make calls to Inference Providers** 权限的 Hugging Face 细粒度访问令牌，用量计入令牌所有者。模型 ID 以模型的制作方开头，因此请以 `huggingface/openai/gpt-oss-120b` 的形式调用，避免请求到达制作方自己的服务商（[请求如何指定模型](../console/models-and-aliases.md#请求如何指定模型)）。路由器默认选择最快的服务商；模型 ID 上的后缀可以指定服务商，例如 `openai/gpt-oss-120b:groq`，或指定策略 `:cheapest` 或 `:preferred`，因此要使用它，请连同后缀添加该模型。每个应用的输出上限都会作为 `max_tokens` 发送给它，`developer` 消息会作为 `system` 消息发送，并省略终端用户的 ID，因为路由器不接受。模型的思考内容来自 `reasoning_content` 或 `reasoning`（取决于路由器背后的服务商发送哪个），可到达任何格式的应用。路由器列出模型时不检查密钥，因此**检查可用性**无法发现错误的密钥；使用该密钥的第一个请求会报告密钥被拒绝。Kaeso 只调用 Chat Completions：路由器只通过 Hugging Face 自己的任务 API 提供嵌入、图像和音频，而 Kaeso 拒绝 Token 计数，因为 Hugging Face 没有记录它。
- **ElevenLabs。** ElevenLabs 的语音、对话、音效、音乐、变声和语音转文本，以 ElevenLabs 自己的格式调用，密钥放在 `xi-api-key` 中。ElevenLabs 不生成文本，因此它服务于[音频 API](../api/audio.md)、[ElevenLabs API](../api/elevenlabs.md)，以及通过其 Veo 和 Seedance 模型服务于[视频 API](../api/videos.md)，不支持聊天。声音按其 ElevenLabs ID 指定。Kaeso 从 ElevenLabs 的 `character-cost` 响应头读取其计费的字符数。如需在欧盟或美国存储数据，请将 ElevenLabs 的[基础 URL](../self-hosting/configuration.md#服务商设置)设为 `https://api.eu.residency.elevenlabs.io` 或 `https://api.us.elevenlabs.io`。
- **MiniMax。** 即 MiniMax 的 Anthropic 兼容 API，提供 `MiniMax-M3` 和 `MiniMax-M3.1-Flash`，这是 MiniMax 在该接口上提供的仅有的模型；它的 M2 模型已下线。Kaeso 以 Messages 格式调用它，密钥放在 `x-api-key` 中，因此各种格式的应用都能访问它。Kaeso 拒绝 MiniMax 接受却不作处理的内容：`top_k`、`stop_sequences`（Chat 应用的 `stop`）、`mcp_servers`、`container`、不为 1 的 `temperature`、不为 0.95 的 `top_p`，以及不为 `auto` 的 `tool_choice`。Claude Code 只清除思考内容的 `context_management` 会被省略，并在 `kaeso-left-out` 中注明。图片可以通过 URL 或 base64 发送，文档由 MiniMax 自己拒绝。`MiniMax-M3.1-Flash` 始终思考，并拒绝关闭思考。MiniMax 自己为思考块签名，因此 Anthropic 应用应只把含有这些思考块的对话发给 MiniMax 模型；Anthropic 会拒绝它们的签名。Kaeso 拒绝 Token 计数，因为 MiniMax 返回的格式与 Anthropic 不同。在中国大陆，请将 MiniMax 的[基础 URL](../self-hosting/configuration.md#服务商设置)设为 `https://api.minimax.cn/anthropic`，并使用 platform.minimax.cn 的密钥。
- **Mistral。** `developer` 消息会作为 `system` 消息发送给它，部分字段以它自己的名称发送，例如 `seed` 改为 `random_seed`；它拒绝其他一些字段（例如 `logit_bias`），也拒绝以助手消息结尾的对话。
- **Moonshot。** 即 Kimi API，提供 Moonshot 的 Kimi 模型，例如 `kimi-k3` 和 `kimi-k2.6`。`developer` 消息会作为 `system` 消息发送给它；应用预填的助手消息会带上 Moonshot 的 `partial: true` 发送，使回复接着该消息续写。它拒绝部分字段，例如 `parallel_tool_calls: false` 和 `store`，因为 Moonshot 接受这些字段却不作处理。Kimi 模型的采样参数是固定的：Kaeso 在发送前拒绝 1 以外的 `temperature`，`top_p`、`n` 和惩罚参数的其他值则由 Moonshot 拒绝。模型的推理内容会以各种格式送达应用。K3 模型的 `reasoning_effort` 为 `low`、`high` 或 `max`，Kaeso 拒绝其他级别；`kimi-k2.6` 在 `none` 时不思考，`kimi-k2.7-code` 始终思考。Kimi 模型在思考时拒绝 `tool_choice: "required"`。
- **Nebius Token Factory。** 即 Nebius 的无服务器开放模型，例如 `zai-org/GLM-5.3`、`moonshotai/Kimi-K3` 和 `deepseek-ai/DeepSeek-V4.1-Flash-1017`；在模型 ID 后加 `-fast` 可选择其更快的版本，请将其作为自定义模型并填写价格添加。`developer` 消息会作为 `system` 消息发送给它，终端用户的 ID 以 `user` 发送，视频以 `video_url` 部分发送给支持视频的模型。模型的思考内容来自 `reasoning_content` 或 `reasoning`，可到达任何格式的应用。它的嵌入模型（例如 `Qwen/Qwen3-Embedding-8B`）提供 `/v1/embeddings`。Nebius 不提供 Messages、图像、音频或Token 计数。公共端点在 Nebius 选择的区域运行；在你选择的区域中的专用端点有自己的主机，例如 `https://api.tokenfactory.eu-north1.nebius.com`，请将其设为 Nebius 的[基础 URL](../self-hosting/configuration.md#服务商设置)。
- **NVIDIA。** 即 NVIDIA 托管的 NIM API，也就是 build.nvidia.com 上的模型，例如 `nvidia/nemotron-3-super-120b-a12b`、`moonshotai/kimi-k2.6` 和 `z-ai/glm-5.3-flash`，以及它的嵌入模型，例如 `nvidia/nemotron-3.5-embed-1b`。你自己运行的 NIM 容器则是 **NVIDIA NIM** 类型的[自定义服务商](../console/custom-providers.md#服务器软件)。模型 ID 以模型的发布方开头，因此请以 `nvidia/moonshotai/kimi-k2.6` 的形式调用，避免请求到达发布方自己的服务商（[请求如何指定模型](../console/models-and-aliases.md#请求如何指定模型)）。每个应用的输出上限都会作为 `max_tokens` 发送给它，`developer` 消息会作为 `system` 消息发送，并省略终端用户的 ID，因为 NVIDIA 的 API 不接受。模型的思考内容来自 `reasoning_content`，可到达任何格式的应用；Nemotron 等模型通过 `chat_template_kwargs` 或 `reasoning_effort` 开启思考，Chat 应用会按原样发送它们。`nvidia/nv-embedqa-e5-v5` 等用于检索的嵌入模型需要 `input_type`（`query` 或 `passage`），只有 Embeddings 应用能发送它。NVIDIA 对它不认识的密钥返回 403，因此应用会将其视为不允许发出该请求的密钥；对已退役的模型，它会在检查密钥之前返回 410。NVIDIA 列出模型时不检查密钥，因此**检查可用性**无法发现错误的密钥；使用该密钥的第一个请求会报告它。Kaeso 拒绝 Token 计数，因为 NVIDIA 不提供。
- **Ollama Cloud。** 由 Ollama 在自己的服务器上运行的模型，例如 `gpt-oss:120b`。模型 ID 保留 Ollama 在冒号后的标签。每个应用的输出上限都以 `max_tokens` 发送给它，因为 Ollama 会忽略 `max_completion_tokens`；它拒绝 `logprobs`、`top_logprobs` 和 `logit_bias`，因为 Ollama 接受这些字段却不作处理。模型的推理内容会以各种格式送达应用。Ollama 的免费套餐只包含部分模型：对其他模型，Ollama 返回 402，应用会将其作为被拒绝的服务商密钥收到。Ollama 列出模型时不检查密钥，因此**检查可用性**无法发现错误的密钥；使用该密钥的第一个请求会报告密钥被拒绝。本地 Ollama 服务器不需要密钥；请将其添加为服务器为 Ollama 的[自定义服务商](../console/custom-providers.md#服务器软件)。
- **OpenAI。** 服务商密钥也可以是一个 ChatGPT 账户，其请求按 OpenAI 的相应规则使用该账户的 ChatGPT 套餐（[使用 ChatGPT 账户登录](../console/provider-keys.md#使用-chatgpt-账户登录)）。
- **OpenRouter。** 模型 ID 包含模型开发者，例如 `anthropic/claude-sonnet-4.5`。请以 `openrouter/anthropic/claude-sonnet-4.5` 的形式调用，这样请求不会发往该开发者自己的服务商（[请求如何指定模型](../console/models-and-aliases.md#请求如何指定模型)）。Kaeso 按目录中的价格记录费用，而不是按 OpenRouter 在 `usage.cost` 中报告的费用。OpenRouter 列出模型时不检查密钥，因此**检查可用性**无法发现错误的密钥；使用该密钥的第一个请求会报告密钥被拒绝。
- **Perplexity。** Perplexity 的 Sonar 模型 `sonar`、`sonar-pro`、`sonar-reasoning-pro` 和 `sonar-deep-research`，它们会搜索网页并附带引用作答，通过 `/v1/sonar` 上的 Sonar Chat Completions 调用。Perplexity 已于 2026-09-27 结束对 Sonar Chat Completions 的支持，并在同一端点后用其 Agent API 作答，因此 KPMR 将 Sonar 模型标为已弃用；Kaeso 不调用 Agent API。Chat 应用的搜索字段，例如 `search_mode`、`search_domain_filter` 和 `web_search_options`，按原样到达 Perplexity，其回复保留 `citations`、`search_results` 和 `related_questions`。其他格式的应用无法发送搜索字段，收到的回答带有 `[1]` 标记，但不含来源。每个应用的输出上限以 `max_tokens` 发送，`developer` 消息以 `system` 消息发送，并省略最终用户的 ID，因为 Perplexity 只在请求头中接收它。Kaeso 拒绝 Perplexity 的 API 参考未列出的工具、对数概率、惩罚参数、`seed` 和 `stream_mode`，以及它不提供的 token 计数。Perplexity 的回复报告的 `usage.cost` 包含搜索费用；Kaeso 按目录中的 token 价格记录成本，不含这笔费用。Perplexity 的模型列表列出的是 Agent API 的模型，而不是 Sonar 的 ID，因此**检查可用性**会把 Sonar 模型判定为无法确定，而不是不可用。
- **QwenCloud。** 阿里巴巴在中国内地以外的模型平台，前身为阿里云百炼国际站（Model Studio），此处为其新加坡地域，提供 `qwen3.7-flash` 等通义千问模型，以及 `kimi-k3` 等其他厂商的模型。密钥只能在创建它的地域使用。对于中国（北京）地域（KPMR 中为 `alibaba-cn`），请将 QwenCloud 的[基础 URL](../self-hosting/configuration.md#服务商设置) 设为 `https://dashscope.aliyuncs.com/compatible-mode`，并使用该地域的密钥；一个实例只能连接一个地域。`developer` 消息会以 `system` 消息发送给它；QwenCloud 接受但不处理的字段（例如 `logit_bias` 和 `web_search_options`）会被拒绝。应用的思考请求以 `enable_thinking` 发送给模型，Anthropic 应用的 `budget_tokens` 以 `thinking_budget` 发送，推理强度只发送给列出了强度级别的模型，例如 `qwen3.8-max`。Chat 应用的 `max_tokens` 只限制回答，不限制思考；`max_completion_tokens` 同时限制两者。有些模型只能思考，会拒绝关闭思考，`qwq-plus` 只回答流式请求：应用会收到 QwenCloud 的 400。它的嵌入模型（例如 `text-embedding-v4`）不在 KPMR 中：请将其添加为以 Embeddings 发送的自定义模型，并填写价格。它的 Wan 视频模型通过同一主机根路径下 DashScope 自己的任务 API 服务于[视频 API](../api/videos.md)，其 OpenAI 兼容模式不提供的图片、语音和转写模型也发往那里的 DashScope 自己的 API（[图片 API](../api/images.md)、[音频 API](../api/audio.md)）。
- **SambaNova。** 即 SambaCloud，SambaNova 托管的模型，例如 `gpt-oss-120b`、`GLM-5.3` 和 `gemma-4-31B-it`。Kaeso 默认调用 Chat Completions；模型的**发送格式**可以选择 Messages，即 SambaNova 兼容 Anthropic 的端点。模型的思考内容来自 `reasoning`，可到达任何格式的应用；DeepSeek-V3.2 和 Gemma 4 只有在 Chat 应用发送 `chat_template_kwargs: {"enable_thinking": true}` 时才会思考。Kaeso 拒绝 `frequency_penalty` 和 `presence_penalty`，因为 SambaNova 接受它们却不生效；并省略终端用户的 ID 和 Responses 应用的缓存键，因为 SambaNova 的 API 不接受它们。Token 计数适用于每个 SambaNova 模型：Kaeso 通过 SambaNova 的 Messages Token 计数来计算。SambaCloud 不提供嵌入和 Whisper；两者都是 SambaStack 的功能。SambaNova 列出模型时不检查密钥，因此**检查可用性**无法发现错误的密钥；使用该密钥的第一个请求会报告密钥被拒绝。对于 SambaStack 安装，请将 SambaNova 的[基础 URL](../self-hosting/configuration.md#服务商设置) 设为其地址。
- **Scaleway。** 即 Scaleway Generative APIs，托管在巴黎的无服务器模型，例如 `gpt-oss-120b`、`qwen3.5-397b-a17b` 和 `mistral-small-3.2-24b-instruct-2506`；Scaleway 将它们保留在欧洲。服务商密钥是带有 Generative APIs 权限集的 IAM API 密钥的私密密钥。它访问该密钥的默认项目；如需访问其他项目，请将 Scaleway 的[基础 URL](../self-hosting/configuration.md#服务商设置) 设为 `https://api.scaleway.ai/<project-id>`。`developer` 消息会作为 `system` 消息发送给它，并省略终端用户的 ID，因为 Scaleway 的 API 不接受。模型的思考内容来自回复中的 `reasoning_content` 和流中的 `reasoning`，可到达任何格式的应用。它的嵌入模型（例如 `bge-multilingual-gemma2`）提供 `/v1/embeddings`，`whisper-large-v3` 只以 `json` 形式提供转录，按音频分钟计费。Scaleway 对它不认识的密钥返回 403，与没有 Generative APIs 权限的密钥相同，因此应用会将其视为不允许发出该请求的密钥。Kaeso 拒绝 Token 计数，因为 Scaleway 不提供。
- **SiliconFlow。** 即 SiliconFlow 的国际 API，提供 `deepseek-ai/DeepSeek-V4-Flash`、`Qwen/Qwen3.5-397B-A17B` 和 `zai-org/GLM-5.3` 等开放模型、`Qwen/Qwen3-Embedding-8B` 等嵌入模型、CosyVoice 语音和 SenseVoice 转录。如需使用 KPMR 列为 `siliconflow-cn` 的中国端点，请将 SiliconFlow 的[基础 URL](../self-hosting/configuration.md#服务商设置) 设为 `https://api.siliconflow.cn`，并使用那里的密钥；一个安装只能访问其中一个。模型 ID 以模型的制作方开头，有些还以其他服务商的 ID 开头，例如 `openai/gpt-oss-120b`，因此请以 `siliconflow/openai/gpt-oss-120b` 的形式调用（[请求如何指定模型](../console/models-and-aliases.md#请求如何指定模型)）。每个应用的输出上限都会作为 `max_tokens` 发送给它，它只限制回答，`developer` 消息会作为 `system` 消息发送，并省略终端用户的 ID，因为 SiliconFlow 的 API 不接受。应用的思考设置会作为 `enable_thinking` 发送给模型，Anthropic 应用的 `budget_tokens` 会作为 `thinking_budget` 发送；模型的思考内容来自 `reasoning_content`，可到达任何格式的应用。语音接受以其模型命名的音色，例如 `FunAudioLLM/CosyVoice2-0.5B:alex`，转录只接受文件和模型。Kaeso 拒绝图像和视频，因为 SiliconFlow 以自己的形式提供它们，也拒绝 Token 计数，因为它不提供。
- **SpaceX。** 即 xAI 的 API，提供 Grok 等模型。作为实验性选项，服务商密钥也可以是套餐包含 API 访问权限的 Grok 账户（[使用 Grok 账户登录](../console/provider-keys.md#使用-grok-账户登录)）。
- **Standard Compute。** 面向前沿模型和开放模型、带每月计算预算的包月套餐。它的路由器 `standardcompute`，即 **Smart routing**，会为每个请求从 Standard Compute 控制台中启用的模型里选择一个，添加 Standard Compute 的模型时排在最前面。它的回复把模型称为 `StandardCompute`；只有 Standard Compute 的请求日志会显示由哪个模型作答。确切的 ID（例如 `anthropic/claude-sonnet-5.5`）会固定使用一个模型，`:eu` 和 `:us` 变体（例如 `openai/gpt-5.6-luna:eu`）只在欧洲或美国的提供商端点上运行。Standard Compute 按套餐计费而不是按 Token 计费，因此它的模型没有价格：请求的费用显示为**未知**，除非管理员手动为这些模型设置价格，否则支出预算会拒绝这些模型（见[支出预算无法计价的功能](../console/limits-and-budgets.md#支出预算无法计价的功能)）。每月预算用完时，应用会收到因计费原因被拒绝的服务商密钥；Standard Compute 的速率限制会以速率限制的形式到达应用，并带有其 `retry-after`。模型的思考会以每种格式到达应用，来自 `reasoning`。Kaeso 只调用 Chat Completions：Standard Compute 的 Messages 端点会忽略思考，它也不提供嵌入、图片或音频。Kaeso 会拒绝 Token 计数（Standard Compute 只根据请求大小估算）和视频（其模型的提供商不接受以链接形式发送的视频）。Standard Compute 列出模型时不检查密钥，因此**检查可用性**无法发现错误的密钥，并且会把密钥列表中缺少的模型判定为无法确定，而不是不可用。如需使用欧盟或美国端点，请将 Standard Compute 的[基础 URL](../self-hosting/configuration.md#服务商设置)设为 `https://eu.stdcmpt.com` 或 `https://us.stdcmpt.com`。
- **Vercel。** 即 Vercel AI Gateway，另一个网关，其自身的路由和回退在 Kaeso 之后运行。模型 ID 包含模型开发者，例如 `openai/gpt-5-nano`。请以 `vercel/openai/gpt-5-nano` 的形式调用，这样请求不会发往该开发者自己的服务商（[请求如何指定模型](../console/models-and-aliases.md#请求如何指定模型)）。模型的**发送格式**可以选择 Vercel 同样提供的 Responses 或 Messages；通过 Messages，Vercel 会把 Anthropic 的 `cache_control` 传给 Claude 模型。Kaeso 按目录中的价格记录费用，而不是按 Vercel 在 `usage.cost` 中报告的费用，后者不含 Vercel 自己的附加费。Vercel 只为 Claude 模型精确计数 Token，对其余模型只做估算，因此 Kaeso 拒绝为任何 Vercel 模型计数 Token。Vercel 回答模型信息时不检查密钥，因此**检查可用性**无法发现错误的密钥；使用该密钥的第一个请求会报告密钥被拒绝。免费套餐的 Vercel 账户无法调用 Claude 等付费模型：Vercel 返回 403，应用会将其视为服务商密钥被拒绝，请求日志中保留 Vercel 给出的原因。
- **Z.ai。** 即 Z.ai 的 Anthropic 兼容 API，提供 `glm-5.3`、`glm-4.6` 等 GLM 模型。Kaeso 以 Messages 格式调用它，密钥放在 `x-api-key` 中，因此各种格式的应用都能访问它，Anthropic 应用的请求按应用原样发送。Z.ai 没有说明它接受哪些 Anthropic 字段，因此 Kaeso 会全部发送，是否拒绝由 Z.ai 决定；重复的提示词由 Z.ai 自动缓存。Z.ai 发送自己的错误码：余额不足（`1113`）以被拒绝的服务商密钥送达应用，而不是速率限制；服务过载（`1305`）以过载送达；提示词过长（`1261`）也以提示词过长送达，这样 Claude Code 会压缩对话。Kaeso 拒绝 Token 计数，因为 Z.ai 没有提供相关说明。**检查可用性**能发现错误的密钥；Z.ai 没有说明模型列表，因此能否发现 Z.ai 不提供的模型尚未验证。Z.ai 按密钥类型对每次调用计费，并且只允许在其列出的编程工具中使用 GLM Coding Plan 密钥，因此请使用标准 API 密钥。在中国大陆，请将 Z.ai 的[基础 URL](../self-hosting/configuration.md#服务商设置)设为 `https://open.bigmodel.cn/api/anthropic`，并使用 bigmodel.cn 的密钥。

## 商标

所有商标和标志均归其各自所有者所有。Kaeso 与这些服务商均无关联，也未获得其认可或赞助。控制台显示服务商的标志，仅用于标明密钥、模型或请求所属的服务商。Anthropic、Cerebras、Cohere、Google、Groq、Z.ai、MiniMax、Standard Compute、Cloudflare 以及 QwenCloud 的所有者 Alibaba Cloud 在其条款中限制使用其标志；Kaeso 仅出于此目的显示它们的标志，保留所有者的形状和颜色，只在颜色需要在 Kaeso 的浅色和深色背景上保持可见时才做必要的调整。Mistral 的品牌页面要求不要给其图标重新着色或加框；Kaeso 以 Mistral 自己的颜色显示该图标，放在与其他标志相同的中性底块上。[NOTICE.md](https://github.com/logicplanes/kaeso/blob/dev/NOTICE.md#trademarks) 列出了每个标志的来源。
