项目的**目录**列出其密钥可调用的模型。请求目录之外的模型会被拒绝。目录位于项目的**模型**页面上。

## 添加模型

选择**添加模型**，选择 OpenAI 或 Anthropic，搜索并选择一个或多个模型；**包含已弃用**会同时列出已弃用的模型，**检查参数**会在添加前显示单个模型的参数。Kaeso 从开放的模型数据库 [models.dev](https://models.dev) 获取每个模型的价格、限制和功能。**添加所有当前 Anthropic 模型**（或 OpenAI 模型）会添加该服务商所有未弃用、且生成文本或嵌入向量的模型，并跳过已在目录中的模型；之后出现的模型不会自动添加。

**添加自定义模型**按 ID 添加模型。如果 models.dev 未收录该模型，需要填写其输入和输出、限制、价格以及所使用的 API 格式。

部署默认每 24 小时刷新一次 models.dev 数据。实例管理员可以在**实例** › **模型来源**下查看其状态并立即同步。models.dev 不再收录的模型会以最后已知的参数保留在目录中，并标记为**已不再收录**；models.dev 标记为已弃用的模型会标记为**已弃用**。

## 可用性

目录中的模型并不一定是服务商向项目的服务商密钥提供的模型：服务商可能已停用它，或者密钥无权访问它。每个模型的侧滑面板会显示其**可用性**：

| 可用性 | 含义 |
| --- | --- |
| 可用 | 在最近一次检查或请求中，服务商提供了该模型 |
| 不可用 | 服务商回复不向此密钥提供该模型；列表中也会标出 |
| 未检查 | 尚无结果，或此后组织的某个服务商密钥发生了变化 |

**检查可用性**会用项目的服务商密钥询问每个模型的服务商是否提供该模型（向服务商发送 `GET /v1/models/{model}`，若其回复找不到，再读取其模型列表 `GET /v1/models`），并报告结果。只有当服务商的列表有响应且不含该模型时，模型才算不可用。无法检查的模型会保留原有的可用性：项目没有该服务商的密钥、服务商拒绝了密钥或未响应、服务商的列表没有响应因而无法确认找不到，或服务商密钥在检查期间发生了变更。Kaeso 也会从请求中得知：当服务商对请求回复找不到模型且其列表证实了这一点时，该模型变为不可用，应用会收到[说明这一点的错误](../api/errors.md#服务商错误)；当对不可用模型的请求成功时，它会重新变为可用。结果只对给出它的密钥有效：如果在检查或请求进行期间服务商密钥发生了变更，其结果不会被记录。

不可用的模型仍保留在目录中，但 `GET /v1/models` 不会列出它，对它的请求仍会发送给服务商；Kaeso 从不会把请求发给其他模型。请为服务商密钥开通该模型的访问权限，或将该模型从目录中移除。检查需要**管理模型**权限，并以 `catalogue_model.check` 记录在审计日志中。

## 模型的参数

模型的侧滑面板显示正在使用的参数及每项参数的来源：models.dev、Kaeso 自身的补充，或在此项目中设置的覆盖值。**编辑覆盖值**仅在此项目中更改参数；**恢复为 models.dev 的值**会将某项参数恢复为来源中的值。如果在侧滑面板加载后有其他人更改了该模型，保存或移除时会提示这一点并加载当前的参数，以便重新进行更改。

| 参数 | 作用 |
| --- | --- |
| 显示名称 | 在控制台中显示的名称 |
| 输入、输出 | 文本、图像、音频、视频、嵌入向量 |
| 上下文、输出上限 | 模型的 Token 限制 |
| 输入价格、输出价格、缓存读取价格和缓存写入价格 | 每百万 Token 的价格，以美元计；用量和预算按请求发出时生效的价格计费 |
| 发送格式 | Kaeso 调用该模型时使用的 API 格式：Anthropic Messages、OpenAI Chat Completions、OpenAI Responses 或 OpenAI Embeddings |
| 工具调用、推理、结构化输出 | 模型支持的功能 |
| 支持温度参数 | 模型是否接受 `temperature` |
| 支持强制工具选择 | 模型是否接受 `tool_choice` 的 `required`、`any` 或指定的工具；对不接受的模型，Kaeso 会在调用服务商之前拒绝此类请求 |
| 自适应思考、推理强度等级 | 模型推理的开启方式，以及其接受的推理强度 |
| 超时 | 对该模型的请求的秒数；留空则使用部署的请求超时 |
| 发布时间 | 模型的发布日期 |

**从目录中移除**会将模型移出目录；此后对它的请求会被拒绝，指向它的别名和包含它的模型列表也会失去它。

## 别名

**别名**是项目自定义的名称，指向其目录中的某个模型，例如用 `fast` 指向 `claude-haiku-4-5`。应用调用别名，更换别名背后的模型时无需更改应用。

在**别名**选项卡上，**创建别名**需要填写名称和目标。名称为 1 到 200 个字符，不含空格和 `/`。与某个模型同名的别名优先于该模型；控制台会将其标记为遮蔽同名模型。

## 请求如何指定模型

请求可以通过三种方式指定模型，Kaeso 按以下顺序查找：

1. 项目的别名：`fast`。
2. 服务商加模型：`anthropic/claude-haiku-4-5`。
3. 模型自身的 ID：`claude-haiku-4-5`。

如果两个服务商有相同 ID 的模型，请使用 `provider/model` 形式。

更改模型、覆盖值和别名需要**管理模型**权限。
