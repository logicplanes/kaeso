项目的模型目录位于其**模型**页面，列出其密钥可以调用的模型。请求目录之外的模型会被 Kaeso 拒绝。更改模型、其参数和别名需要**管理模型**权限。

## 添加模型

选择**添加模型**，然后在搜索框旁的可搜索列表中选择服务商，并搜索其模型。组织已连接的服务商排在前面。对话框会记住所选服务商，直到重新加载控制台或退出登录。如果组织没有该服务商的[服务商密钥](provider-keys.md)，对话框会提示：在有人添加密钥之前，对其模型的请求都会失败。

对话框按从新到旧列出模型，每个模型都显示其上下文窗口以及输入和输出价格。匹配的模型超过 50 个时，对话框只显示前 50 个并说明共有多少个匹配，可通过搜索缩小范围。选择一个或多个模型并添加。**包含已弃用**会同时列出已弃用的模型，**检查参数**可在添加前查看模型的参数。

每个模型的价格、限制和能力都来自 [models.dev](https://models.dev)，一个开放的模型数据库。另有两个快捷方式：

- **添加所有当前 OpenAI 模型**（其他服务商同理）会添加该服务商所有未弃用的文本和嵌入模型。它会跳过目录中已有的模型，之后出现的新模型不会自动添加。对话框会说明将添加多少个模型，达到 50 个或更多时会在添加前提醒。
- **添加自定义模型**按 ID 添加模型。如果 models.dev 未收录该模型，需要填写其输入和输出、限制、价格，以及 Kaeso 调用它所用的 API 格式。ID 不能是 `.` 或 `..`，也不能在斜杠之间包含它们，因为 URL 会丢弃这一部分。

对于组织的[自定义服务商](custom-providers.md#添加其模型)，对话框改为列出该服务商自身模型列表中的模型 ID，所有值都由您手动填写。

实例默认每 24 小时刷新一次 models.dev 数据，实例管理员可在[模型来源](instance-administration.md#同步模型数据)下查看其状态。models.dev 不再收录的模型会以最后已知的参数保留在目录中，并标记为**已不再收录**。models.dev 标记为已弃用的模型会标记为**已弃用**。

## 查找模型

**目录**标签页按服务商对模型分组。可以只显示一个服务商的模型、具备某项能力（例如**工具调用**或**图片输入**）的模型，或打开**仅已覆盖**，只显示在此项目中更改过参数的模型。在手机上，这些筛选项位于**筛选**下。排序菜单按**模型 ID**、**输入价格**或**最新发布**对每个服务商的模型排序。

## 可用性

目录中的模型不一定都由服务商提供给项目的服务商密钥。服务商可能已下线该模型，或该密钥无权访问它。列表会将此类模型标记为**不可用**，每个模型的侧滑面板会显示其**可用性**：

| 可用性 | 含义 |
| --- | --- |
| 可用 | 服务商在最近一次检查或请求中提供了该模型 |
| 不可用 | 服务商表示不向此密钥提供该模型 |
| 未检查 | 尚无结果，或组织的某个服务商密钥此后发生了变更 |

选择**检查可用性**，使用项目的服务商密钥询问每个模型的服务商。只有当服务商回复“未找到”且其模型列表确认缺少该模型时，Kaeso 才会将模型标记为不可用。Kaeso 无法检查某个模型时，该模型保持原有可用性，报告会说明原因。例如项目没有该服务商的密钥，或服务商拒绝了该密钥，即使只是其模型列表拒绝了它。

请求也会更新可用性。当服务商对请求回复“未找到”且其模型列表确认时，模型会变为不可用，应用会收到[说明这一情况的错误](../api/errors.md)。当对不可用模型的请求成功时，模型会重新变为可用。每个回复只对收到它的服务商密钥有效。

不可用的模型仍保留在目录中，Kaeso 会直接以该错误答复对它的请求，而不调用服务商。请求绝不会转给其他模型。模型 API 的模型列表（`GET /v1/models`）不包含该模型。

要解决此问题，可以为服务商密钥开通该模型的访问权限，或将模型从目录中移除。每隔五分钟，Kaeso 会放行一个请求到服务商以重新确认。密钥获得访问权限后，模型会自动恢复为可用；选择**检查可用性**则会立即更新。审计日志会记录每次检查。

## 更改模型的参数

模型的侧滑面板显示**当前使用的值**及每个值的来源：models.dev、Kaeso 自己的补充，或本项目设置的覆盖值。**编辑覆盖值**只在本项目中更改这些值，**恢复为 models.dev 的值**可将某个值恢复为来源值。如果在侧滑面板加载后有其他人更改了该模型，保存时会提示并加载当前值，以便您重新进行更改。

| 参数 | 含义 |
| --- | --- |
| 显示名称 | 控制台中显示的名称 |
| 输入、输出 | 输入：文本、图片、PDF、音频和视频。输出：文本、图片、音频和嵌入 |
| 上下文、输出上限 | 模型的 Token 限制 |
| 输入、输出、缓存读取和缓存写入价格 | 每百万 Token 的美元价格。用量和预算按请求发生时的价格计算。缓存写入价格是 models.dev 所列的 5 分钟价格。写入 Anthropic 1 小时缓存按输入价格的两倍计费（[Anthropic 的规则](https://platform.claude.com/docs/en/about-claude/pricing)），模型没有输入价格时按缓存写入价格计费 |
| 发送格式 | Kaeso 调用该模型所用的 API 格式：Anthropic Messages、OpenAI Chat Completions、OpenAI Responses 或 OpenAI Embeddings |
| 工具调用、推理、结构化输出 | 模型支持的能力 |
| 温度 | 模型是否接受 `temperature` |
| 强制工具选择 | 模型是否接受将 `tool_choice` 设为 `required`、`any` 或指定工具。对于不支持的模型，Kaeso 会在调用服务商之前拒绝此类请求 |
| 自适应思考、推理强度 | 如何开启模型的推理，以及模型接受的推理强度 |
| 超时 | 对该模型的请求可持续的秒数。留空则使用实例的请求超时 |
| 发布时间 | 模型的发布日期 |

## 移除模型

在模型的侧滑面板中选择**从目录中移除**。此后 Kaeso 会拒绝对该模型的请求，引用它的别名和模型列表也会失去它。

## 创建别名

别名是项目为其目录中某个模型自定的名称，例如用 `fast` 指代 `claude-haiku-4-5`。应用将别名作为模型名发送，您可以更换其背后的模型而无需改动应用。

在**别名**标签页上选择**创建别名**，填写名称和**目标**。名称为 1 到 200 个字符，不能包含空格或 `/`。别名优先于同名模型，列表会将其标记为**遮蔽同名模型**。

## 请求如何指定模型

Kaeso 按以下顺序查找请求指定的模型：

1. 项目的别名：`fast`。
2. 服务商和模型：`anthropic/claude-haiku-4-5`。
3. 模型 ID：`claude-haiku-4-5`。

如果两个服务商有相同 ID 的模型，请使用 `provider/model` 形式。Kaeso 在第一个 `/` 处拆分，因此包含 `/` 的模型 ID 保持不变：`togetherai/Qwen/Qwen3.5-9B` 指 Together AI 的 `Qwen/Qwen3.5-9B`。

模型 ID 可以包含 `/`，例如 OpenRouter 的 `anthropic/claude-sonnet-4.5` 或 Groq 的 `openai/gpt-oss-20b`。Kaeso 先按“服务商/模型”查找，再按模型 ID 查找，因此以另一个服务商 ID 开头的名称会发往该服务商。项目中同时有 OpenRouter 的 `openai/gpt-4o` 和 OpenAI 的 `gpt-4o` 时，`openai/gpt-4o` 调用 OpenAI。要确保调用正确的模型，请在前面加上服务商：`openrouter/openai/gpt-4o` 始终调用 OpenRouter 的模型，`groq/openai/gpt-oss-20b` 始终调用 Groq 的模型。
