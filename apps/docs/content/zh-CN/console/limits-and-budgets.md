限额用于限制项目、成员或服务账号，以及密钥的请求数、Token 和支出。请求必须通过适用于它的每一项限额：其密钥、所有者和项目的限额。

## 添加限额

1. 在项目的**限额**页面上选择**添加限额**。
2. **适用于谁？** 选择项目、某个成员或服务账号，或某个密钥。
3. **设置什么限额？** 选择类型、额度、周期和模型。对于预算，还要选择是否为硬性以及何时提醒。

页面列出每项限额及其已用量。**全部**、**项目**、**成员**和**密钥**分别只显示一个层级。成员、服务账号或密钥的限额也会显示在其侧滑面板中。

查看限额需要**查看限额**权限，更改限额需要**管理限额**权限。

## 限额类型

| 类型 | 计量 | 周期 |
| --- | --- | --- |
| 支出预算 | 美元，按模型价格计算 | 一天、一个月或总计 |
| Token 预算 | Token | 一天、一个月或总计 |
| 请求速率 | 请求数 | 滑动的一分钟 |
| Token 速率 | Token | 滑动的一分钟 |

天和月指 UTC 的自然日和自然月，总计永不重置。限额可以适用于所有模型，也可以只适用于某一个模型。

限额不能高于上一层级的同类限额。密钥的支出预算不超过其所有者的，成员的不超过项目的。

## 硬性和软性预算

速率限制始终拒绝超出的请求，且没有提醒。开启**用尽后拒绝请求**时，预算为硬性，新限额默认开启。硬性预算会拒绝请求，直到周期重置。软性预算会放行请求，只发送提醒。

预算最多可在其额度的 10 个百分比处提醒，默认为 50%、80% 和 100%。每到一个提醒点，Kaeso 会给组织的所有者和管理员以及项目的管理员发送邮件。对于密钥的预算，密钥所有者也会收到邮件。每个人都可以在账户中关闭**预算提醒**。

## 支出预算无法计价的功能

Kaeso 按 token 为请求计价。有些功能还会按次计费或按更高费率计费，Kaeso 无法统计这部分费用。因此，只要请求适用任何支出预算（无论硬性还是软性），当请求使用以下功能时，Kaeso 都会在请求到达服务商之前以状态码 403 拒绝它：

- 由服务商运行的工具，例如 Anthropic 的 `web_search` 或 `code_execution`，或 OpenAI 的 `web_search`、`file_search`、`image_generation`、`code_interpreter` 或 `mcp`，Kaeso 把 OpenAI 的 `web_search` 发给 Claude 时也算在内；
- `mcp_servers`、`web_search_options`、OpenRouter 的 `plugins` 或 xAI 的 `search_parameters`；
- `auto`、`default`、`flex`、`on_demand` 或 `standard_only` 以外的 `service_tier`，例如 `priority`；
- `anthropic-beta` 中的 `context-1m-…`，它会按更高费率对长提示词计费；
- 没有输入或输出价格、或价格为零的模型，除非管理员在该模型上手动设置了这个价格。Embeddings 只需要输入价格。

由应用自己运行的工具可以使用：函数和自定义工具，Anthropic 的 `bash`、`text_editor`、`computer` 和 `memory`，以及 OpenAI 的 `local_shell`、`apply_patch`、`computer_use_preview` 和对函数进行归组的 `namespace` 工具。token 预算和速率限制不会拒绝这些功能；没有支出预算时，所有功能都可以使用。

要使用此类功能，请使用不受任何支出预算约束的密钥调用：密钥本身、其所有者和项目都没有支出预算。错误消息会指出该功能和预算所在的层级，例如“This key has a spend budget that can't price `web_search_20250305`; ask an admin.”

## 更改限额

编辑限额可更改其额度；对于预算，还可更改提醒和是否为硬性。要更改类型、周期或模型，请移除该限额后重新添加。

如果在页面加载后有其他人更改了该限额，保存时会提示并加载当前限额。请在此基础上重新进行更改。

## 应用看到的内容

Kaeso 会以应用自身的 API 格式对被拒绝的请求返回状态码 429，消息中会指明是哪项限额：

- 超出速率限制时，消息说明何时可以重试，`Retry-After` 响应头给出秒数。
- 预算用尽时，消息说明预算何时重置。

当仍在进行中的请求可能用尽某项硬性预算或 Token 速率时，Kaeso 会以 `Retry-After: 1` 拒绝下一个请求，直到这些请求完成。每个进行中的请求都会按模型价格占用其最高可能费用。这包括按其大小估算的输入，以及其输出上限（`max_tokens` 或 `max_output_tokens`，否则为模型自身的上限）。流式请求在运行期间一直占用。

输入按模型的输入价格和各项缓存价格中最高的一项计算。如果请求要求使用 Anthropic 的 1 小时缓存，其中也包括 1 小时缓存写入价格，即输入价格的两倍。

SpaceX 的上限不包括推理，因此发往 SpaceX 推理模型的请求占用模型自身的输出上限。ChatGPT 账户无法发送输出上限，因此通过它发出的请求同样占用模型自身的输出上限。在预算下，请求至少占用该周期或之前 30 天内平均每个请求的费用。

如果请求的费用可能超过某项硬性预算或 Token 速率的剩余额度，即使没有其他请求在运行，Kaeso 也会拒绝它。消息会要求减少输出 Token。如果较早的请求移出这一分钟后 Token 速率足以容纳该请求，消息则会说明何时可以重试。若要在较小的预算下并行运行更多请求，请发送更低的输出上限。

如果请求未设置输出上限，且所用模型既没有输出上限也没有上下文窗口，Kaeso 就无法限定它。没有其他请求在运行时，这样的请求会放行，因此它可能单独超出限额。如果硬性预算在其周期内及之前 30 天内没有已完成的请求，这样的请求会单独运行。

> [!NOTE]
> Kaeso 在 Valkey 中统计限额。Valkey 无法访问期间，速率限制和软性预算会放行请求，硬性预算会以状态码 503 拒绝请求。
