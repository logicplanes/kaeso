description: 查看项目处理的每个请求，将其导出，并选择保留哪些内容。

每个模型请求都会被记录：模型、服务商、状态、Token、费用、耗时、密钥以及发送者。开启内容日志后，请求和回复也会被保存。条目在请求结束几秒后出现。

## 列表

项目的**请求日志**页面按从新到旧列出请求，时间范围为过去 1 小时、1 天、7 天、30 天或自选范围。

- **添加筛选**可按密钥、成员、模型、服务商、状态、错误类型、回复是否为流式，以及来源（API 或试验场）缩小列表。**仅失败**只显示错误。
- **实时**会在新请求到达时将其添加到列表；向下滚动后，会有一个按钮显示新请求的数量。
- 显示选项用于选择列和密度。
- **按 ID 打开请求**可通过应用收到的 `kaeso-request-id` 查找请求。

## 单个请求

选择一个请求即可打开：

| 选项卡 | 显示内容 |
| --- | --- |
| 概览 | 结果、路由、发送者、耗时、流的进度和用量 |
| 请求 | 应用发送的内容 |
| 回复 | 应用收到的内容 |
| 原始数据 | 以 JSON 形式显示两者 |

查看提示词和回复需要**查看提示词和输出**权限。没有该权限，或内容未被记录或已超过保留期时，选项卡会注明这一点。嵌入向量从不保存。

失败的请求会显示其错误类型，例如**触发速率限制**、**上下文过长**、**超时**或**客户端已断开**，并在有服务商消息时显示该消息。中途中断的流式回复会记录为失败，并注明其进行到的位置。

## 导出

**导出**会下载符合当前筛选条件的请求，格式为 CSV、JSON Lines 或包含内容的 JSON Lines。导出需要**导出日志**权限，导出内容还需要**查看提示词和输出**权限。

## 保留期

保存哪些内容以及保存多久，按组织在**组织设置** › **日志记录**下设置：

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 记录请求内容 | 开 | 是否随日志条目保存请求和回复 |
| 元数据保留期限 | 90 天 | 条目的保存时长 |
| 内容保留期限 | 30 天 | 请求和回复的保存时长；不会超过元数据的保留期限 |

部署设置新组织的默认值，以及组织可选的最长保留期。缩短保留期会删除较早的条目；延长保留期只对新条目生效。更改这些设置需要**管理日志设置**权限。

项目可以在其**设置**下为自身关闭内容日志，但组织关闭内容日志时，项目无法开启。

## 存储和删除

**日志记录**下的**存储**选项卡按项目显示组织的条目数量及其占用的空间。在**删除记录**选项卡上，**删除日志**会永久删除所选的若干完整 UTC 日的日志，范围可以是所有项目或某一个项目；用量和费用会保留。需要输入 `delete`（中文界面中为“删除”）确认，列表会显示每项删除为排队中或已完成。删除需要**删除日志**权限，并需要近期登录过。
