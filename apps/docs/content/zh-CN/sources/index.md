来源让直接调用服务商的客户端（例如 Claude Code、Codex 或 LiteLLM 代理）把这些请求上报给项目。这些请求随后会出现在项目的请求日志、用量、费用和限额中，并标记为已观测（[来源](../concepts/sources.md)说明了 Kaeso 如何统计它们）。查看**来源**需要 `sources.view`，添加和更改来源需要 `sources.manage`。

## 添加来源

1. 打开项目的**来源**，选择**添加来源**。
2. 选择由谁向 Kaeso 上报，例如 **Claude Code**，然后选择**继续**。
3. 为来源命名，例如 `Claude Code，Ada 的笔记本`，并选择其请求记在谁名下：您自己或项目的某个服务账号。
4. 保持**按邮箱匹配成员**开启，让带有成员邮箱地址的事件计入该成员。开启**保留提示词和回复**以保留客户端发送的内容。
5. 选择**添加来源**。

Kaeso 只显示一次来源密钥，并附上连接其客户端的具体配置：环境变量、设置文件、钩子或网关配置。请立即复制密钥，因为 Kaeso 只保留它的哈希。把这些配置放到对应位置，然后使用一次客户端。对话框会等待第一个事件，然后显示**已连接**和收到的内容，或 Kaeso 拒绝它的原因。

## 跟踪来源

**来源**列出每个来源的客户端、最近一次上报时间、最近 14 天的拒绝次数、每天的事件数和状态：

| 状态 | 含义 |
| --- | --- |
| **等待中** | 还没有事件 |
| **已连接** | 最近一天内有上报 |
| **空闲** | 更早之前有上报 |
| **已停用** | 在重新开启前，Kaeso 拒绝它发送的内容 |
| **已归档** | 它的密钥已失效；它的请求会保留 |

打开一个来源，可以查看它每天的活动，包括 Kaeso 忽略的重复和拒绝的内容。来源详情还会显示最近一次拒绝的原因，以及带有密钥占位符的设置方法。**查看请求**会打开只含其请求的请求日志。

在请求日志中，已观测的请求带有**已观测**标记，并在本应显示密钥的位置显示其来源。**上报来源**筛选条件显示某个来源的请求，**来源**筛选条件显示所有已观测的请求。**分析**可以**按来源**细分用量，把网关自己的请求和各个来源的请求分开；工具调用日志会显示来源上报的 MCP 调用。

## 更改来源

在来源详情中，您可以：

- 重命名来源，或更改其请求记在谁名下。
- 开启或关闭**按邮箱匹配成员**或**保留提示词和回复**。
- 关闭**接收它的事件**，让 Kaeso 拒绝它发送的内容，例如在迁移客户端期间。
- 选择**换一个新密钥**。旧密钥立即失效，请把新密钥填入客户端的设置。
- 选择**归档来源**。归档是永久的：密钥失效，来源的请求保留在日志中。
